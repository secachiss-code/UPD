# Архитектура upd 0.2.2

Этот документ описывает реализацию в исходниках, сценарии запуска и размещение системных данных. Точка входа — `src/main.rs`; все подсистемы входят в один бинарник.

## Модули

| Модуль | Ответственность |
|---|---|
| `main.rs` | Разбор CLI, повышение привилегий, порядок обновления, установка/удаление, генерация systemd-файлов и хуков. |
| `common.rs` | Структура `Config`, JSON-состояние, atomic write, `flock`, команды ОС, сеть, батарея, диск, reboot и поиск процессов со старыми библиотеками. |
| `backend.rs` | Trait `Backend` и адаптеры `Pacman`, `Apt`, `Rpm` для пакетных менеджеров. |
| `mirrors.rs` | Определение сети, кандидаты зеркал, параллельные пробы, оценка свежести и скорости, предзагрузка обновлений. |
| `extras.rs` | Flatpak, AUR, fwupd, новости Arch, snapper/timeshift, перезапуск служб. |
| `vpn.rs` | Подписки и профили, генерация YAML, REST-контроллер mihomo, ядро, геофайлы, systemd, системный прокси GNOME. |
| `tui.rs` | Экран состояния, меню, просмотр списков, настройка зеркал и вкладки VPN. |

Общие зависимости: `ureq` для HTTP, `serde`/`serde_json`/`serde_yaml` для состояния и профилей, `ratatui` для интерфейса, `libc` для системных вызовов и `sha2` для сверки релизного файла mihomo.

## Обновление и хранение состояния

`upd update` берёт блокировку `/var/lib/upd/.lock`, затем вызывает подбор зеркал и `mirrors::gather`. Сборщик обновляет пакетные индексы, получает списки системных пакетов и доступных интеграций, рассчитывает размер загрузки и записывает `updates.json`. Далее CLI предлагает прочитать новости Arch, загружает пакеты, делает снапшот, запускает транзакцию пакетного менеджера и выполняет послетранзакционные проверки.

`upd auto` использует ту же подсистему, но без интерактивной установки и проверки AUR. На батарее проверка выполняется, а предзагрузка обычно пропускается. В лимитной сети функция завершает фоновую задачу до обновления зеркал, VPN и списка обновлений. Штатный пропуск завершается с кодом `0` и сохраняет причину; сбой проверки пакетов, предзагрузки или записи состояния возвращает ненулевой код, который systemd фиксирует как неуспешный запуск.

Для Flatpak фоновая команда проверяет и предзагружает только system installation. Ручные `upd check` и `upd update`, запущенные через `sudo` или `doas`, дополнительно проверяют и обрабатывают per-user installation вызывающего пользователя.

Для pacman база синхронизации проверки находится отдельно от системной базы — `/var/lib/upd/syncdb`. Это позволяет получить список обновлений и сравнить его с установленными пакетами без изменения основной базы pacman. После транзакций pacman/apt установленные хуки вызывают `upd reconcile`, который повторно сравнивает список с сохранённым состоянием без сетевого запроса.

### Пакетные менеджеры

- **pacman**: временная sync-база, `pacman -Qu`, предзагрузка `-Sw`, обновление `-Syu`. На Garuda используется `garuda-update`; для Manjaro выбор зеркал остаётся за `pacman-mirrors`.
- **apt**: `apt-get update`, симуляция `full-upgrade`, загрузка через `apt-get -d`, установка через `apt full-upgrade`. Для зеркал редактируются источники основного архива и сохраняются их исходные версии.
- **dnf/dnf5/yum**: менеджер сам выбирает зеркала; загрузка выполняется в режиме download-only.
- **zypper**: менеджер сам выбирает зеркала; для Tumbleweed и Slowroll используется `dup`.

Выбор реализации выполняется по доступным командам в `PATH`, в порядке pacman, apt-get, zypper, dnf5/dnf/yum. Идентификатор системы берётся из `os-release`.

### Подбор зеркал

Источники кандидатов объединяются в порядке: пользовательский `mirror` из `/etc/upd.conf`, закреплённый блок пакетного менеджера, автоматически найденные либо первые зеркала из текущего списка. URL дедуплицируются. Для каждого кандидата скачивается до 3 МиБ; быстрые отказы и ранее рабочие зеркала повторно замеряются последовательно, в том числе если первый проход не нашёл рабочего кандидата.

Если backend предоставляет endpoint свежести, зеркала сравниваются по дате синхронизации. Скорость сглаживается экспоненциальным средним в статистике отпечатка сети. Лучшие результаты сохраняются в `/var/lib/upd/mirrors.json`; менеджер получает первые `keep` зеркал, а его прежний список остаётся запасным. История сетей старше 30 дней удаляется.

Отпечаток формируется из сетевого интерфейса, шлюза, MAC шлюза и имён обнаруженных TUN-интерфейсов. Проверка использует `/proc` и `/sys` и не делает внешний сетевой запрос.

## Службы, установка и упаковка

`upd install` размещает ручную установку в `/usr/local/bin` и `/etc/systemd`; пакетная — использует `/usr/bin` и `/usr/lib/systemd`. Пакетный сценарий установки вызывает `upd install --package`: он переносит остатки ручной установки и включает таймеры. Файлы генерирует `upd gen-files <каталог> <arch|deb|rpm>`.

В зависимости от системы создаются:

- `upd-auto.service` и `upd-auto.timer` — проверка и предзагрузка;
- `upd-net.service` и `upd-net.timer` — проверка смены сети;
- `upd-mirrors.path` и `upd-mirrors-apply.service` — возврат закреплённых зеркал после изменения mirrorlist Arch;
- `upd-notify.service` и пользовательский `upd-notify.timer`;
- `upd-vpn.service` — запуск mihomo от root с `ExecStartPre=upd vpn prepare`;
- pacman/apt hook для `reconcile` и dispatcher NetworkManager.

При отсутствии systemd ручная установка добавляет расписание в `/etc/cron.d/upd`, если cron-каталог существует. Удаление останавливает службы, снимает маркеры Garuda и просит backend вернуть исходные зеркала. Настройки VPN, подписки и общий каталог состояния намеренно сохраняются.

Сборка пакетов выполняется `package.sh`: он компилирует бинарник, запрашивает у него файлы установки для каждого формата, затем вызывает nfpm. Версия nfpm закреплена в скрипте; архив проверяется по опубликованному рядом списку SHA-256.

## VPN

`upd vpn add` загружает профиль и классифицирует его как Clash/mihomo YAML либо список URI. Адрес, профиль и ключ REST API хранятся отдельно. YAML профиля используется как основа, после чего `build_config` задаёт локальные порты и секрет контроллера, TUN, DNS-настройки, авто-группу и порядок пользовательских/локальных/региональных правил. Часть ключей подписки намеренно переопределяется.

Mihomo предоставляет API на `127.0.0.1:9097`, закрытый случайным токеном. `vpn::snapshot` использует API для состояния групп, задержек и трафика. Переключение сервера закрывает старые соединения, чтобы выбор применился сразу.

При загрузке релизов сначала используется прямой запрос, затем локальный прокси работающего `upd-vpn`, а затем обнаруженный прокси-порт процесса `FlClashCore`. Для первоначального `upd vpn start` недостающие файлы загружаются с видимым прогрессом; если FlClash активен, программа просит закрыть его перед запуском `upd-vpn`. Служба также проверяет и подготавливает конфигурацию непосредственно перед запуском.

`upd auto` обновляет подписки по сроку и проверяет релизы FlClash/Mihomo. При появлении нового релиза FlClash скачивается подходящее ядро mihomo, сверяется обязательный SHA-256 digest из GitHub API, проверяется возможность запуска и затем файл атомарно заменяет прежнее ядро. При отсутствии digest установка отменяется. Геофайлы загружаются из релизов `MetaCubeX/meta-rules-dat`.

## Пути и права доступа

| Путь | Данные | Права, задаваемые приложением |
|---|---|---|
| `/etc/upd.conf` | Общая конфигурация и список предпочитаемых зеркал | `0644` |
| `/var/lib/upd/` | JSON-состояние, логическая блокировка, временная база pacman | Каталог `0755`, JSON `0644` |
| `/etc/upd/vpn/subs.json` | URL подписок, названия и состояние загрузки | Каталог `0700`, файл `0600` |
| `/etc/upd/vpn/secret` | Секрет API mihomo | Каталог `0700`, файл `0600` |
| `/etc/upd/vpn/rules.txt` | Пользовательские VPN-правила | Файл `0600` |
| `/var/lib/upd/vpn/` | Ядро, конфигурация, профили и геофайлы | Каталог `0700`; сгенерированный конфиг и профили `0600` |
| `/var/lib/upd/private/apt-*` | Оригинальные и применённые APT sources, их права и журнал восстановления транзакции | Каталог `0700`, файлы `0600` |
| `/etc/apt/upd-mirrors.list` | Список зеркал, используемый через `mirror+file:` | Файл `0644` |

Общие JSON-файлы не содержат URL подписок: для пользовательского VPN-состояния публикуются название, хост, срок, трафик и ошибки. Механизм установки использует root-права для системных пакетных транзакций, зеркал, systemd, TUN и прошивок.

## Ограничения и эксплуатационные заметки

- Приложение собирается как x86_64 Linux-бинарник; ядро VPN подбирается для уровня CPU x86_64 v1/v2/v3.
- Подписки принимают только HTTPS URL; перенаправления проверяются вручную, разрешены до пяти переходов только на HTTPS.
- При отсутствии SHA-256 digest в метаданных релиза mihomo установка отменяется.
- Сборка `package.sh` должна выполняться на Linux-системе, где `upd gen-files` может обнаружить один из поддерживаемых менеджеров пакетов.
- Фоновое состояние рассчитано на один системный экземпляр `/var/lib/upd`; тестовый/альтернативный каталог задаётся переменной `UPD_STATE_DIR`.

## Разработка

Цель сборки и `CC` для musl задаются в `.cargo/config.toml`. Основные команды:

```sh
rustup target add x86_64-unknown-linux-musl
./build.sh
./package.sh
```

Встроенные тесты расположены в модулях `src/*.rs`; тест TUI рендерит несколько экранов через `TestBackend`. Изменения конфигурации следует сверять с `Config::defaults`, `Config::load`, `Config::save` и текстом пользовательской документации.
