# Настройки cm 0.2.8

Главный конфигурационный файл: `/etc/cm.conf`; путь можно заменить переменной окружения `CM_CONF`. При первом запуске от root файл создаётся со значениями по умолчанию. Его можно редактировать вручную или изменять часть параметров через TUI. Булевы значения задаются числами: `1` — включено, `0` — выключено. Неизвестные ключи и строки без `=` игнорируются; строки, начинающиеся с `#`, являются комментариями.

Список пользовательских зеркал задаётся повторяющимися строками `mirror = URL`. URL добавляются к автоматическому поиску и закреплённым зеркалам, а не заменяют их. Если конфигурационный файл уже существует, но строк `mirror` нет, предпочтительных зеркал не будет.

## Язык

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `lang` | `auto` | Язык интерфейса: `ru`, `en`, `de`, `it`, `zh`, `ar` или `auto` — по локали системы (`LC_ALL` → `LC_MESSAGES` → `LANG`; незнакомая локаль — английский). Задаётся при ручной установке, командой `cm lang КОД` или в TUI (пункт «Язык / Language»). |

## Обновление и зеркала

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `keep` | `3` | Сколько лучших зеркал закреплять в начале списка. При чтении `1`–`10`. |
| `timeout` | `10` | Таймаут одного замера зеркала, секунды. При чтении `2`–`120`. |
| `extra_from_list` | `8` | Сколько зеркал из текущего системного списка дополнительно замерять. При чтении `0`–`64`. |
| `rescan_count` | `15` | Сколько результатов брать из автопоиска. При чтении `3`–`64`. |
| `retries` | `5` | Число попыток предзагрузки пакетов. При чтении `1`–`20`. |
| `mirror_max_age_h` | `12` | Возраст замера в часах, после которого зеркала проверяются снова. При чтении `1`–`87600`. |
| `network_memory_days` | `3` | Сколько дней использовать сохранённые лучшие зеркала знакомой сети. При чтении `0`–`365`. |
| `max_lag_h` | `3` | Максимальное отставание зеркала от самого свежего, часы. При чтении `1`–`87600`. |
| `parallel` | `4` | Одновременные замеры зеркал без обнаруженного VPN/TUN. При чтении `1`–`16`. |
| `parallel_vpn` | `2` | Одновременные замеры при обнаруженном VPN/TUN. При чтении `1`–`16`. |
| `mirror` | зависит от менеджера при первом создании файла | Предпочтительное зеркало; можно задать несколько строк `mirror = URL`, учитываются первые 64. |

Значения вне диапазона не делают конфиг ошибочным: при чтении они сжимаются к ближайшей границе, чтобы экстремальное число не плодило потоки и не останавливало обновление пакетов. Повторный замер зеркал делается только для временных ошибок (таймаут, обрыв, HTTP 429 и 5xx), не больше 16 адресов, пулом до 4 потоков и в пределах общего бюджета времени.

## Предзагрузка и дополнительные компоненты

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `prefetch` | `1` | Заранее скачивать системные пакеты в фоне. |
| `prefetch_on_battery` | `0` | Разрешить фоновую загрузку от батареи. При `0` проверка остаётся, загрузка откладывается. |
| `prefetch_on_metered` | `0` | Разрешить фоновую задачу в лимитной сети. При `0` она целиком пропускается. |
| `min_free_gb` | `2` | Требуемый запас свободного места после загрузки, ГБ. При чтении `0`–`1048576`. |
| `flatpak` | `1` | Проверять, предзагружать и устанавливать обновления Flatpak, если команда доступна. `cm check` и `cm update` охватывают system installation и per-user installation вызывающего пользователя; `cm auto` работает только с system installation. |
| `aur` | `1` | Проверять и обновлять AUR через установленный `paru`/`yay` при ручном обновлении от пользователя. `cm auto` AUR не проверяет. |
| `firmware` | `1` | Проверять прошивки через fwupd и предлагать установку после обновления системы. |
| `news` | `1` | Проверять новости Arch перед обновлением на Arch и производных, кроме Manjaro. |
| `snapshot` | `1` | Делать снапшот перед обновлением, если пакетный менеджер не делает это сам. |

## VPN

| Ключ | По умолчанию | Значение |
|---|---:|---|
| `vpn_tun` | `1` | Включить TUN для всего системного трафика. При `0` остаётся локальный прокси. |
| `vpn_autostart` | `1` | Включать службу mihomo при загрузке. Настройка применяется при запуске VPN или установке `cm` с уже добавленной подпиской. |
| `vpn_direct_ru` | `1` | Направлять домены и IP России напрямую по правилам и геофайлам. |
| `vpn_direct_lan` | `1` | Направлять частные сети напрямую. |
| `vpn_auto_select` | `1` | Создать группу `⚡ Авто`, выбирающую сервер по задержке. |
| `vpn_dns` | `1` | Включить собственный DNS mihomo с fake-IP и DNS-over-HTTPS. При `0` DNS-секции в конфиге нет, mihomo пользуется системным DNS; DNS из профиля подписки не переносится. |
| `vpn_ipv6` | `0` | Включить IPv6 в конфигурации mihomo и DNS. |
| `vpn_allow_lan` | `0` | Разрешить подключения к прокси с других устройств в LAN. |
| `vpn_port` | `7897` | Порт локального HTTP/SOCKS-прокси. При чтении ограничивается `1`–`65535`; для VPN допустим `1024`–`65535`, а при `vpn_dns = 1` нельзя использовать `1053` (порт своего DNS). Проверяется при сборке VPN-конфига и в TUI. |
| `vpn_mode` | `0` | Маршрутизация: `0` — `rule`, `1` — `global`, `2` — `direct`. |
| `vpn_sub_update_h` | `12` | Интервал по умолчанию в часах для новых подписок без интервала от провайдера. Значение записывается в карточку при добавлении; изменение ключа не меняет интервал уже добавленных подписок. Заголовок `profile-update-interval` провайдера имеет приоритет. При чтении `1`–`87600`; интервал провайдера ограничивается так же. |
| `vpn_core_check_h` | `24` | Период проверки релизов ядра VPN в часах. При чтении `1`–`87600`. |

При загрузке конфигурации `vpn_port` ограничивается диапазоном `1`–`65535`, а `vpn_mode` — диапазоном `0`–`2`. Негодный для VPN порт не мешает остальным командам cm: ошибку сообщает сборка VPN-конфига. Порт `9097` больше не занят — API mihomo работает через Unix-сокет.

Для подписок принимаются только HTTPS-ссылки. Перенаправления ограничены пятью переходами, каждый адрес назначения должен оставаться на HTTPS. Сохранённая ранее HTTP-подписка не обновится, а уже скачанный профиль не удаляется автоматически. Для миграции запросите у провайдера HTTPS-ссылку, добавьте её через `cm vpn add`, переключитесь на неё командой `cm vpn use N`, затем удалите старую через `cm vpn del N`. Вместо номера обе команды также принимают стабильный `id:ИД`, если он известен.

Пользовательские правила хранятся отдельно в `/etc/cm/vpn/rules.txt` и идут раньше правил локальной сети, России и подписки. Секретный URL подписки находится в `/etc/cm/vpn`; не помещайте их в общедоступные файлы и резервные копии без соответствующей защиты.

## Где меняются параметры

- `/etc/cm.conf` — зеркала, предзагрузка, интеграции и основные параметры VPN.
- `cm` → экран «Зеркала» — количество закрепляемых зеркал и список предпочтительных адресов.
- `cm` → экран VPN → «Настройки» — режим, маршрутизация, DNS, автозапуск, авто-выбор, LAN, порт и интервалы.
- `cm vpn rules` — открыть редактор правил VPN.

Пример короткого фрагмента:

```ini
prefetch = 1
prefetch_on_battery = 0
min_free_gb = 4
keep = 3
mirror = https://mirror.example.org/$repo/os/$arch
vpn_mode = 0
vpn_tun = 1
```


## Сохранение и применение из CLI/TUI и помощника

Config::save выполняет межпроцессную транзакцию: при сохранении старого снимка
изменяются только его изменённые поля; добавления/удаления mirror объединяются.
Atomic write использует уникальный private temp, fsync файла и каталога.
Внутренняя revision позволяет отличить фактически сохранённое состояние.
Ручное редактирование сторонним редактором не участвует в flock приложения.

Диапазоны для интерактивного изменения общие (`number_setting`): недопустимое
значение отклоняется до записи. Legacy конфиги при чтении по-прежнему clamped,
как описано выше. При изменении vpn_port проверяются 1024–65535 и конфликт
1053 с включённым собственным DNS **до commit**.

Ответ помощника содержит фактический config, revision и runtime:
NotNeeded (применять нечего), Applied, Pending (используется при следующем
запуске/нет подписки) или SavedButNotApplied (сохранено, применение не удалось,
причина и способ повторить). Сохранение не выдаётся за успешный runtime-apply.
COSMIC открывает TUI; прежний графический редактор настроек удалён.

При смене подписки кандидат собирается и проверяется через mihomo до записи
активного выбора. Если служба работает, конфиг применяется через API; выбор
сохраняется после успешного применения. При ошибке восстанавливаются старые
конфиг и подписка, включая случай ошибки fsync после успешного rename. Ошибка
отката сообщается отдельно. Эти действия защищены блокировками VPN и подписок.

Последний отказ сохраняется в `last-error.json` в каталоге VPN (0600).
В опубликованное состояние попадает сообщение с удалёнными URL и известными
секретными полями профиля. TUI и `cm vpn status` показывают этап, подписку, время
и причину; успешная операция отмечает прежнюю ошибку как устранённую.

UserContext для пользовательского proxy определяется по peer UID или CLI
invoking user; фоновые задачи без пользователя пропускают sysproxy. Ambient
окружение daemon не выбирает владельца proxy. Ошибки gsettings/dconf видны.

[AUDIT-LUNA6-LOCKS.md](AUDIT-LUNA6-LOCKS.md).
