## 2. Уточнения I02-модели до исполнения S01–S13

Это работа архитектора, а не тестировщика. Перечень нужен, чтобы контракт хранения стал исполнимым:

1. **Идентичность Node между поколениями.** Сохраняет ли неизменённый узел свой id в поколении N+1 или получает новый? От ответа зависят S03, S04 и S09.
2. **`Verification.generation`.** Чьё это поколение: Source или TunnelInstance? Ось NET в S09 нельзя проверить без ответа.
3. **Туннель хоста.** У HostPolicy есть только `connection_profile_id`, ссылки на TunnelInstance нет. Ожидание S10 «туннель хоста остановлен в модели записей» сейчас не наблюдаемо.
4. **Единственный источник членства в группе.** Назначение хранится и в ApplicationDefinition, и в `ApplicationGroup.application_ids`. Нужен один авторитетный источник или инвариант согласованности с отдельной проверкой.
5. **EnvironmentProfile.** Владелец — «сессия», а в примерах профиль привязан к приложению. Где хранится выбранный preset до запуска?
6. **Завершённые Session и удаление (S05).** Блокирует ли историческая Session удаление Source? Где хранится запрет повторного использования id: tombstone или отдельный реестр?
7. **Конкурентное обновление (S08).** Вместо «одно поколение либо отказ обоих» нужна точная норма: ровно одна запись фиксируется с generation +1, вторая получает явный conflict с ожидаемым поколением. Отказ обоих допустим только при отказе хранилища и тогда отдельно помечается.

### W0-1 (= C17a): не-install команда рядом с legacy-следом

**Цель.** Наблюдать фактические записи production-кода для команд, отличных от `install`, когда рядом лежит след UPD. Это характеризующий тест известного пробела, а не приёмка миграции.

**Бинарник.** Отладочная сборка `cargo build` текущего дерева, offline, по зафиксированному lockfile. Это разрешено контрактом I01. `build.sh` и `package.sh` запрещены.

**Предварительная проверка (до любого запуска).** Прочитать путь `main()` до разбора команды: `conf_lang()`, `backend::detect()` с конструктором выбранного backend, `default_mirrors()`, а также `Config::load` и `Config::save` и всё, что они вызывают. Координатор уже видел, что `detect()` проверяет наличие `pacman` через `have()` без запуска (`src/backend.rs:93-106`), а `Config::load` только читает файл. Конструкторы backend не прочитаны. Если там есть внешние команды, сеть, systemd/D-Bus или запись вне `conf_path()`, сценарий получает BLOCKED с указанием места в коде. Выполнять его в этом случае нельзя.

**Песочница.** Обязательные свойства; конкретный инструмент выбирает тестировщик:

| Свойство | Требование | Доказательство |
|---|---|---|
| euid 0 без root хоста | user namespace с отображением себя в 0 (`unshare -Urm` или `bwrap --unshare-user --uid 0`) | `id -u` внутри = 0, снаружи ≠ 0 |
| Без сети | новый net namespace (`--net` / `--unshare-net`) | `ip -j link` внутри: только `lo` |
| Запись не уходит на хост | overlayfs с upper в scratch поверх `/etc` и `/var/lib`, либо bwrap `--tmp-overlay` | список upper-каталога = полный перечень записей процесса |
| Нет связи с systemd/D-Bus хоста | tmpfs поверх `/run`, переменные `DBUS_*` сняты | отсутствие `/run/systemd/private` и `/run/dbus` внутри |
| Ловушки внешних команд | первым в `PATH` каталог заглушек `sudo doas run0 pkexec systemctl pacman apt-get dnf zypper nmcli ip nft iptables curl`. Заглушка пишет argv в журнал и выходит с кодом 97. Заглушка `pacman` нужна и для того, чтобы `have("pacman")` выбрал тот же backend, что на хосте; её запуск — всё равно срабатывание ловушки | журнал ловушек |
| Окружение | `env -i` + `PATH`, `LANG=C.UTF-8`, `HOME` в scratch. Никаких `CM_*` и `UPD_*` (R04) | дамп env внутри без значений секретов |

Реальные `/etc/upd.conf`, `/etc/upd`, `/var/lib/upd`, `/run/upd` хоста внутри песочницы скрываются whiteout'ом или tmpfs. Там, где сценарий требует след, кладётся синтетический файл с маркером `W0-SENTINEL` и известным SHA-256.

**Сценарии и предсказание по коду.** Свойство безопасности **P-C17a**: при legacy-следе команда, отличная от `install`, не изменяет ни одного legacy-файла и не создаёт `/etc/cm.conf`.
