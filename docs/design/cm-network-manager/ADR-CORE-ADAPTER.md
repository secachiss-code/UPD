# ADR: контракт CoreAdapter (I04.T01.a)

Статус: готово к ревью координатора. Продуктовых решений пользователя здесь нет.

Дата: 2026-10-06.

## Что фиксирует trait

`CoreAdapter` (`src/core/adapter.rs`) — общий lifecycle для mihomo, будущего Xray и in-memory fake:

- `capabilities`, `validate`, `start`, `stop`, `reload`, `health`, `statistics`;
- три независимые оси: `ApiReady`, `RouteReady`, `RemoteReachable`;
- `CoreError` и `Debug` конфига не содержат байтов конфига, URL и секретов;
- `CoreStatistics` — счётчики API этого instance. Их не складывают со счётчиками хоста или интерфейса TUN.

Fake (`src/core/fake.rs`) используется тестом lifecycle в `tests/audit_i04_adapter.rs`. Это не набор соответствия mihomo.

Дескриптор pinned mihomo 1.19.32 (`src/core/mihomo.rs`) не копирует таблицы: он возвращает те же срезы, что `src/sources/capabilities.rs`.

## Что trait не гарантирует

- `ApiReady` не означает, что маршруты установлены.
- `RouteReady` не означает, что выбранный удалённый узел доступен.
- `RemoteReachable` не означает, что трафик пользователя идёт в туннель.
- `validate` не запускает процесс и не меняет сеть хоста.
- `reload` без рестарта обещан только если `capabilities.reload_without_restart` истинно. Для ядра, у которого этого нет, вызывающий получает `Unsupported` либо явный рестарт на следующем слое, а не тихий успех.
- Успешный `stop` идемпотентен. Повторный `start` при уже запущенном ядре — `Conflict`.
- `health` остановленного ядра — успешное наблюдение `Down`, а не ошибка.
- Отказ, подставленный fake, не меняет прежнюю готовность и не выглядит как успех.
- Счётчики после `stop` обнуляются и не выдаются за остаточный трафик.
- Fake не открывает сокеты, не создаёт устройства и не является проверкой реального ядра.
