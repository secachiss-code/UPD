## Правила

1. **Код продукта не менять.** Исключений нет. Файлы `tests/hostq/` и `docs/…/tools/accept.py` — код роли 1, их тоже не менять.
2. Тесты — `tests/audit_fin_*.rs` и доработка `tests/audit_ab_*.rs`; общий код — `tests/fin_support/mod.rs` (можно использовать `tests/ab_support`, `tests/pack_support`); фикстуры — `tests/fixtures/fin/`; стенды — `tests/ab_stand.py` (доработка) и `tests/fin_stand.py`, их запускают `tests/audit_ab_e2e.rs` и `tests/audit_fin_e2e.rs`.
3. Свои проверки формата положи в `tests/check_fin_tests.sh` (его вызывает `tests/check_fin.sh` роли 1; `tests/check_audit.sh` и `check_fin.sh` не править): `rustfmt --edition 2024 --check tests/audit_fin_*.rs tests/fin_support/mod.rs`, `python3 -m py_compile tests/fin_stand.py`, `python3 docs/design/cm-network-manager/tools/test_lint.py --dags AB,FIN`. Существующие файлы не переформатировать: никаких `cargo fmt` и `rustfmt` по файлам, которых нет в проверке формата.
4. Временные каталоги — `TempDirGuard`. В тестах задавать `CM_CONF=/nonexistent/cm.conf`: конфиг хоста меняет язык вывода.
5. **Стенд:** `unshare -U --map-root-user --map-auto -n -m`, tmpfs на `/run`. `unshare -r` не годится там, где контроллер запускает ядро или приложение. `/sys` внутри — от хоста: интерфейсы смотреть через `ip`. `curl` — только с `-q` и `--noproxy '*'`. Сеть хоста не меняется. Шаги `tests/hostq/` запускаются только с `CM_HOSTQ_FAKE` или с `CM_HOSTQ_STAND=1` внутри пространства имён стенда.
6. Настоящий `pkcheck` не вызывается: подменный `Authorizer` либо `CM_HELPER_ALLOW=1`.
7. Без секретов и настоящих подписок: узлы — подставные прокси на стенде, источники страны — HTTP на стенде. Пароль и uuid узлов стенда — заведомо вымышленные строки; их отсутствие в выводе проверяется.
8. Проверки с ядром — при `CM_TEST_MIHOMO`; без переменной они печатают SKIPPED и не засчитываются.
9. Коммит — только по поручению пользователя. Сдача — отчёт и evidence.
10. **Gate:** `CARGO_TARGET_DIR=$HOME/.cache/cm-grok-target CM_TEST_MIHOMO=$HOME/.cache/cm-cores/mihomo/mihomo CM_TEST_XRAY=$HOME/.cache/cm-cores/xray/xray sh tests/check_audit.sh`. В дереве лежит незакоммиченная работа: `git checkout`, `git stash`, `git reset`, `git clean` запрещены.

### Рамки прохождения

- **У каждого значения — своя проверка с меткой.** Значения ребра нумеруются с единицы в порядке списка. В Rust перед проверкой стоит комментарий `// [CM02.3]`, не дальше 12 строк за ним — `assert`. В стенде — `ok("CM02.3", "имя", условие)`. Одна проверка может нести несколько меток, если действительно проверяет несколько значений.
- **Значение — ожидаемый результат, а не пример.** Сравнивается именно он: текст команды, код ответа, код выхода, число, строка вывода.
- **`tools/test_lint.py`** работает в двух режимах. Обычный (в gate): у каждого значения есть метка; отключённый тест с записью о дефекте и `defect(...)` в стенде считаются меткой. Строгий (`--strict`, при приёмке): отключённых тестов и `defect(` нет.
- **Запрещённые формы проверки** (их находит `tools/test_lint.py`, и они же — отказ при ревью):
  - условие, истинное всегда: `True`, `or True`, `>= 0`, `assert!(true)`, `|| true`;
  - несколько допустимых исходов: `x in (...)`, `a or b`, «код 0 или 3». Если значение ребра называет два исхода явно («ok и not_running — успех»), это две проверки на двух разных состояниях;
  - проверка константы или типа вместо поведения там, где значение описывает поведение;
  - проверка, что команда «завершилась», без сравнения результата;
  - ожидание без паузы и ожидание без предела.
- **Время.** «Не позже чем через N с» — опрос каждые 200 мс до N секунд; успех раньше срока — PASS, срок вышел — FAIL.
- **Тайм-аут запроса** — `curl -m 5`, код выхода 28 и отсутствие HTTP-кода. Код 7 там, где ожидается тайм-аут, — FAIL, и наоборот.
- **Ноль прямых пакетов.** На интерфейсе «интернета» ведётся счётчик по адресу источника `10.213.0.0/16`. Значение больше нуля в любом сценарии — дефект P0.
- **Свойства** — 10 000 случаев на детерминированном генераторе с записанным начальным значением; контрпример печатается целиком.
- **Устойчивость.** Стенд — 5 прогонов подряд; gate — 3 прогона подряд. Один красный прогон — не PASS.
- **SKIPPED и заблокированные значения — не PASS.**

### Вилка приёмки: что делать с каждым исходом

Ни один исход не требует вопроса пользователю. Работа по остальным рёбрам продолжается всегда.

| Исход | Признак | Что делает роль 2 | Кто действует дальше |
|---|---|---|---|
| **PASS** | проверка зелёная на точном значении | метка, строка в evidence | — |
| **Дефект** | код не выполняет значение ребра | тест остаётся как написан; ставится `#[ignore = "дефект CM02.3"]` (в стенде — `defect("CM02.3", …)` вместо `ok`); запись в `defects.json`: ребро, номер, ожидалось, получено, как воспроизвести, `severity` | роль 1, правило 16 её брифа |
| **Дефект P0** | прямой пакет мимо туннеля, чужой uid, запись контроллера по ссылке пользователя, секрет в выводе | то же, `severity` P0, запись первой; сценарии этого раздела стенда, которые зависят от дефекта, пропускаются с причиной, остальные идут | роль 1 — раньше всего остального |
| **Спор по спецификации** | значение ребра противоречит ADR, лаборатории или другому ребру | проверить более строгий из двух вариантов; запись в `interpretations` evidence: что противоречит чему, что проверено | координатор |
| **Нельзя проверить на стенде** | нужна настоящая машина, настоящий узел или человек | запись в `tests/fixtures/<пакет>/blocked.json`: ребро, номер, причина, шаг очереди хоста, который это проверит. Только уровни L2–L4, не больше 12 на пакет | пользователь запускает названный шаг |
| **Нестабильно** | проверка проходит не каждый раз | не PASS. Найти причину. В стенде (гонка, ожидание без опроса) — исправить стенд. В продукте — дефект с пометкой `race` | роль 2 либо роль 1 |
| **Ошибка самой проверки** | фикстура, порядок шагов, путь | исправить; дефектом не записывать | роль 2 |
| **Код не готов** | вершина в отчёте роли 1 помечена `open` | проверки её рёбер пишутся по спецификации и ставятся `#[ignore = "дефект <ребро>.<n>"]` с `severity` P1 и текстом `не реализовано` | роль 1 |

Чего делать нельзя ни при каком исходе: ослаблять проверку до прохождения; принимать два исхода; заменять поведение константой; удалять значение из списка; править код продукта.

**Круги.** После правок роли 1 снять `#[ignore]` с исправленных дефектов, прогнать, обновить evidence. Кругов — не больше двух. Что осталось красным после второго, уходит координатору списком; пользователю — только итог.

**Пакет принят**, когда:
- `tools/test_lint.py --dags AB,FIN --strict` → EXIT 0: меток хватает, в `tests/audit_ab_*.rs` и `tests/audit_fin_*.rs` нет `#[ignore]`, в стендах нет `defect(`;
- gate — три прогона подряд EXIT 0 без SKIPPED; оба стенда — пять прогонов подряд;
- дефектов P0 и P1 нет;
- `accept.py --check` печатает итог; до запуска пользователем шагов очереди хоста он обязан быть `blocked` только по строкам с `who = user`.

**Evidence:** `docs/design/cm-network-manager/fin-evidence/<дата>/summary.json` — rev, rustc, команды, счётчики gate, вывод `test_lint.py`, PASS/FAIL по каждому ребру и значению, `interpretations`, число проверок стендов по разделам; `defects.json` — рядом. Для рёбер AB — файл `ab.json` той же формы.

## Рёбра

### RP01 · R.P1 → R.Z (L1)

- **Контракт:** Политика читается только из объекта JSON ограниченного размера.
- **Как проверить:** `tests/audit_ab_policy.rs`.
- **Ожидаемые значения:**
  - [ ] `parse(b"[]")`, `parse(b"null")`, `parse(b"1")`, `parse(b"\"x\"")` → `Err(NetError::Unsupported)`
  - [ ] `parse(b"{}")` → политика по умолчанию: ipv6 Block, fake_ip Forbidden, lifetime Pinned, failure Block
  - [ ] объект длиной `MAX_POLICY_BYTES + 1` (допустимый JSON, дополненный пробелами) → `Err`
  - [ ] `{"lifetime":"refcount","extra":1}` → `Err`: неизвестное поле

### RW01 · R.W1 → R.Z (L1)

- **Контракт:** Автоматическая остановка срабатывает каждый раз, а не только первый.
