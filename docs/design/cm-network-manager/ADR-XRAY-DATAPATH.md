# ADR: путь данных Xray для сети приложения (I05.T02.a)

Статус: измерено координатором 2026-10-10. **Xray как ядро туннеля приложения не поддержан**: нужна схема с отдельным пространством имён, её в пакете нет. Xray остаётся ядром-прокси на порту (вершина `I05.X2` прошлого пакета).

## Что измерено

Скрипт: [tools/xray_tun_lab.sh](tools/xray_tun_lab.sh), Xray 26.3.27 (закреплённая версия), входящий `protocol: tun`.

| Как запущен Xray | Результат |
|---|---|
| с привилегиями, TUN создаёт сам | TCP из сети приложения — HTTP 200; UDP — ответ получен. Устройство непостоянное: после `kill -9` его нет |
| под uid пользователя без привилегий, TUN заранее создан CM и принадлежит этому uid | отказ запуска: `failed to create server > operation not permitted` |

Входящий TUN у этой версии есть и пропускает TCP и UDP. Но открыть заранее созданное устройство без `CAP_NET_ADMIN` Xray не может. Для mihomo тот же сценарий работает ([ADR-TUN-OWNERSHIP](ADR-TUN-OWNERSHIP.md)).

## Варианты

| Вариант | Цена |
|---|---|
| Дать Xray `CAP_NET_ADMIN` в сети хоста | Отказ: ядро разбирает чужие данные подписки; с этим правом оно меняет маршруты и фильтр всей машины |
| Свой netns для Xray, где он создаёт TUN сам; сеть приложения подключается к нему, наружу — veth и NAT на хосте | Новый путь данных: отдельная лаборатория, новые команды, NAT. Блокировка при сбое строится иначе |
| Не поддерживать | Туннели приложений работают только на mihomo |

Выбран третий вариант до отдельного решения. В модели данных ядро туннеля — только mihomo (`KernelKind::Mihomo`), поэтому выбрать Xray для приложения нельзя.

## Что остаётся открытым

- `I05.T02.b` (DNS Xray), `I05.T05.a` (проверка на тестовом сервере), `I10.T02.b` (пробы DNS Xray) — зависят от пути данных.
- Причина отказа не разобрана до системного вызова.
