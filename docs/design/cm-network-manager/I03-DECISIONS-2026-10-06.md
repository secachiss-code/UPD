# I03: решения D1, D2, D3

Дата: 2026-10-06. Решения приняты пользователем по рекомендации координатора. Основание — [материалы Grok](grok-review/) `D1-brief.md`, `D2-brief.md`, `D3-brief.md` и сравнение с текущим CM 0.2.8 (`src/vpn.rs`): legacy-путь уже принимает группы, правила и провайдеров и передаёт `skip-cert-verify` в ядро без отметки. Поэтому отказ был бы регрессом, а молчаливое принятие оставляет пользователя без информации.

Все три решения используют один механизм — **явный частичный импорт**: что не импортировано или ослаблено, записывается в закрытом артефакте и в безопасной сводке, пользователь подтверждает. Это не silent dropping.

Исполнитель: Composer 2.5 по [очереди](COMPOSER-QUEUE-2026-10-06.md); ревью: Grok 4.7 по [очереди](GROK-QUEUE-2026-10-06.md); план: [REMAINING-DAG-PLAN](REMAINING-DAG-PLAN-2026-10-06.md).

## Общий механизм: пропуски и подтверждение (`I03.T04.y`)

- **Схема.** Новая версия схемы Store (I02) с полем `ImportOmissions` в provenance источника: список секций, которые не применены (только имена из закрытого набора), счётчики пропущенных строк по классам (`UnsupportedScheme`, `UnsupportedFeature`, `Malformed`) с номерами строк, и число узлов с отключённой проверкой сертификата. Ни текста строки, ни URI, ни значений полей. `deny_unknown_fields` сохраняется: поле добавляется в схему явно, со сменой версии и миграцией существующих записей (пустой набор пропусков).
- **Отметка TLS узла.** У узла с TLS — поле `tls_verification`: `Verified` (обычная проверка), `Pinned` (задан `fingerprint` или `name-cert-verify`: ядро проверяет pin своим verifier, [`component/ca/config.go`](https://github.com/MetaCubeX/mihomo/blob/88dcbf7f1614a67c3b36b848ee3592dfa92ada36/component/ca/config.go#L101)), `Disabled` (`skip-cert-verify: true` без pin). Поле входит в определение узла и в digest.
- **Подтверждение.** Импорт с непустыми пропусками или с узлами `Disabled` не публикуется сразу: pipeline возвращает `PendingConfirmation` со сводкой и её digest. Публикация требует явного `accept_omissions(<digest сводки>)`. Подтверждение хранится в provenance источника. Пока UI нет, подтверждение — параметр API и CLI-флага; интерфейс — в V.02 и I17.
- **Автообновление** (`cm auto`, таймер, refresh без пользователя). Новое поколение публикуется автоматически, только если:
  1. сводка пропусков не шире подтверждённой: те же имена секций, те же классы строк, а число `Disabled`-узлов не превышает подтверждённое;
  2. принято больше 0 узлов;
  3. число узлов не упало больше чем на 50% от предыдущего поколения.

  Иначе остаётся прежнее поколение, причина пишется в last failure без секретов, при ручном запуске пользователь видит вопрос.

## D1. Группы, правила, провайдеры в native-подписке

**Решение: вариант 2 сейчас; вариант 3 — обязательная задача I04 до переключения пользователей на новый путь.**

| Секция | Поведение импорта I03 |
|---|---|
| `proxies` | Импорт узлов, как и сейчас. |
| `proxy-groups`, `rules`, `sub-rules` | Не применяются. Имя секции — в `ImportOmissions`, подтверждение. Содержимое остаётся в закрытом сыром теле (`SourceArtifact::raw_body`) для будущего разбора без повторной загрузки. |
| `rule-providers` (любой `type`) | Не применяются, имя секции — в `ImportOmissions`. Сети нет. |
| `proxy-providers` `type: inline` | Узлы из `payload` разбираются теми же правилами, что `proxies`, и импортируются: данные локальные, сети и путей хоста нет. Ошибка любого узла — по правилам D3 для строки. |
| `proxy-providers` `type: http` | Без сетевого запроса. Секция — в `ImportOmissions`. |
| `proxy-providers` `type: file` | Путь хоста не читается. Секция — в `ImportOmissions`. |
| Неизвестный `type` провайдера | `UnsupportedFeature`, документ отвергается: ядро считает это ошибкой. |
| Итог 0 узлов | Отказ источника целиком с типизированной причиной: например, подписка состоит только из remote-провайдеров. Пустой источник не публикуется. |

**Почему не вариант 1:** большинство реальных подписок содержит группы и правила; новый импорт не взял бы то, что CM 0.2.8 уже принимает.

**Почему вариант 3 не сейчас:** типизированные группы и правила нужны генератору конфига, это работа I04 (`I04.T04.f`).

**Условие для среза V.** До `I04.T04.f` переключение `cm vpn use source:ID` (`V.04`) для источника с пропущенными `rules`/`proxy-groups` выдаёт предупреждение: маршрутизация издателя не применяется, весь трафик идёт через группу CM и пользовательские правила. Пользователь подтверждает или остаётся на legacy-пути.

## D2. `skip-cert-verify`

**Решение: принимать как явный insecure-признак с отметкой. Не отвергать и не принимать молча.**

- Отсутствует или `false` → `tls_verification: Verified`, без отметки.
- `true` вместе с `fingerprint` или `name-cert-verify` → `Pinned`, без предупреждения: ядро проверяет pin.
- `true` без pin → `Disabled`. Узел импортируется. Число таких узлов входит в сводку и требует подтверждения на источник. Отметка видна в статусе узла, в `doctor`, позднее в TUI. Генератор передаёт поле в ядро только для `Disabled`/`Pinned`.
- Узел с `Disabled` не показывается как проверенный (`Verified`) ни на одной оси. Будущий автовыбор (I16) ставит такие узлы ниже, но не исключает.
- Применяется ко всем протоколам, где поле есть в pinned ядре: VLESS, VMess, Trojan, HTTP/SOCKS5 при `tls: true`, Hysteria2, TUIC, а также obfs-опции Shadowsocks, если плагин поддержан. У WireGuard поля нет — `UnsupportedField`.
- URI (`I03.T04.r`): `insecure=1` (Hysteria2), `allowInsecure=1` (Trojan) и аналоги отображаются в то же поле и дают тот же результат. Неявное `true`, которое ставит конвертер ядра для socks, **не** воспроизводится: значение берётся только из явного параметра.
- Отметка — поле узла `tls_verification`, а не новое значение `Verification`: оси NET/REGION/STATE/APP не меняются.

## D3. Смешанный список URI и base64

**Решение: рабочие строки импортируются, пропущенные перечисляются. Источник падает целиком только при порче или нуле узлов.**

| Ситуация | Поведение |
|---|---|
| Строка с неподдержанной схемой | Пропуск, класс `UnsupportedScheme`, номер строки, имя схемы только из закрытого известного списка; иначе `other`. |
| Строка поддержанной схемы с неподдержанной функцией | Пропуск, класс `UnsupportedFeature`. |
| Строка поддержанной схемы, не разбирается | Пропуск, класс `Malformed`. |
| Пустые строки и пробелы | Игнорируются, это не пропуск. |
| Испорчен base64-слой всего тела, HTML, заглушка, пустое тело | Отказ источника; HTML и заглушка — повтор со следующим UA по `negotiate_source`. |
| После пропусков 0 узлов | Отказ источника целиком. |
| Есть хотя бы один узел и непустые пропуски | `PendingConfirmation`, дальше по общему механизму. |

Текст строки, URI, userinfo и значения параметров не попадают ни в сводку, ни в ошибки, ни в evidence.
