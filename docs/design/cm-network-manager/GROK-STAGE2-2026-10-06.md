## Правила (без исключений)

1. **Перед каждой сдачей — полный `sh tests/check_audit.sh`, EXIT=0.** На этапе 1 работа дважды сдавалась с красным gate. Сдача без зелёного gate не принимается. Gate теперь включает `clippy -D warnings -D clippy::undocumented_unsafe_blocks` по всему крейту: новый `unsafe` без `// SAFETY:` роняет сборку.
2. Сборка только `--offline --locked`, `CARGO_TARGET_DIR=~/.cache/cm-grok-target` (`/tmp` — маленький tmpfs).
3. Без установки, без изменений сервисов, сети хоста и файлов legacy (`/etc/upd`, `/var/lib/upd`, `~/.config/cm`). Сеть — только loopback и namespaces harness.
4. Ни секретов, ни настоящих подписок в фикстурах, ошибках, `Debug` и evidence. Неподдержанный ввод — явная ошибка, не молчаливый пропуск.
5. Evidence — только `summary.json` (D8): команда, счётчики, ревизия, хеши, статусы PASS/FAIL/SKIPPED/NOT_RUN. SKIPPED никогда не записывается как PASS.
6. Новые модули — в формате rustfmt. Добавлять их в список `rustfmt --check` в gate.
7. Временные каталоги в тестах — только через `TempDirGuard`.
8. Коммиты делает координатор после ревью. Сдача — отчёт и `summary.json` пакета.
9. Нельзя выдавать за готовое то, что не проверено. Если пункт не закрыт, так и пишется: «открыто, причина».

### Пакет A1 — `V.02` CLI только для чтения (M)

- `cm source list | show <id> | import --dry-run | doctor` — подкоманды в `src/main.rs`, строки в i18n на все 6 языков.
- `import --dry-run`:
  - источник: `--url-stdin`, `--url-file <path>` (файл не шире 0600 своего uid — та же проверка, что `read_secret_file`) или `--from-legacy <N>` (читает `subs.json`, нужен root);
  - транспорт настоящий: `negotiate_source` и `pipeline`;
  - вывод: формат, число узлов по типам, пропуски D1/D2/D3 с причинами, actual UA, TLS-статусы;
  - **ничего не записывает**: ни Store, ни legacy.
- `doctor`: диагностика источника без изменения работающего VPN.
- **Готово, когда:**
  - фикстура с локальным HTTP-сервером (127.0.0.1) печатает узлы и отказы;
  - тест доказывает, что legacy-файлы и Store не изменились (сравнить хеши и mtime каталога до и после);
  - URL и секреты не попадают в вывод, ошибки и argv;
  - в отчёте — точная команда, которой пользователь проверит настоящую подписку.
- Ревью: полное, со свежим контекстом.

### Пакет B — генератор config mihomo, валидация, H.11 с ядром (L+M+XL, критический путь)

Объединено, потому что V.03 и I04.T04.a — один генератор: пишется один раз в `src/core/mihomo/config.rs`, а V.03 его вызывает.

1. **`I04.T04.a`**:
   - узлы всех поддержанных протоколов → `proxies`; DnsPolicy профиля; listeners instance (через `core::worker::generate`, запреты `HOST_LISTENER_KEYS` сохраняются);
   - корпус дополнить так, чтобы каждый тип из `src/sources/capabilities.rs` встречался хотя бы раз;
   - **готово, когда** корпус I03 → config → `mihomo -t` проходит без расхождений, плюс собственные проверки значений (порт, uuid, обязательные поля) отвергают то, что `-t` пропускает.
2. **`V.03`**: узлы Store → config. Авто-группа, пользовательские `rules.txt`, DNS как в legacy. Diff с legacy-генерацией (`src/vpn/config.rs`) на обезличенных фикстурах объяснить в отчёте построчно.
3. **`I04.T04.b`**:
   - `mihomo -t -d <sandbox>`; разбор stderr в фиксированные коды (обобщить `core_validation_reason`);
   - **готово, когда** ни одна ошибка не содержит строк конфига, имён серверов или секретов. Тест с маркером-секретом в узле.
4. **`H.11`, часть с ядром**:
   - в remote-namespace — mihomo-inbound как тестовый сервер (без внешней сети); worker — настоящий mihomo с config из шага 1; клиент → worker → сервер; захват счётчиком nft или tcpdump;
   - без `CM_TEST_MIHOMO` или user namespaces — SKIPPED;
   - **готово, когда** `unshare -rn sh tests/netharness/core.sh` печатает `CORE_OK`, а тест cargo его прогоняет.

После B разблокируются `I04.T03.b` (ADR TUN) и `I04.T04.c` (lifecycle). Их не начинать до ревью B.

### Пакет A2 — `I04.T02.d` legacy host wrapper (M)

- Текущий cm-vpn как instance `host-legacy` за trait `CoreAdapter` (`src/core/adapter.rs`), файл `src/core/legacy_host.rs`. Поведение пользователя не меняется.
