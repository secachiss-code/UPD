# ADR: контроллер Q08 (I06.T01.a)

Дата: 2026-10-06. Статус: рекомендация к подтверждению координатором. Пока она не опровергнута, `I06.T01.b` и следующие задачи I06 исходят из последствий в конце.

## Контекст

Пользователь 2026-10-03 выбрал A+C (Q02 в [QUESTIONS.md](QUESTIONS.md)): CM владеет маршрутами и firewall, profile workers и namespaces владеют туннелями. Q08 спрашивает, куда класть привилегированные сетевые операции. Q16 ставит планку: два пользователя; чужие credentials не читаются; чужая session не управляется.

Координатор предложил небольшой helper и supervised systemd units на каждый worker. База уже есть: `src/core/unit.rs` (текст юнита, `CORE_BIN` вне каталога записи, hardening) и `src/helper/mod.rs` (polkit, `SO_PEERCRED`, строки JSON).

## Варианты

1. Расширить нынешний helper (`/run/cm/helper.sock`, один процесс, polkit-действия `io.github.cm.status`, `io.github.cm.check`, `io.github.cm.vpn`, `io.github.cm.manage`).
2. Отдельный `cm-netd` со своим сокетом и своей копией проверки peer.
3. Тот же небольшой helper для привилегий плюс отдельный systemd unit на каждый worker.

## Критерии

**Пакетные операции против сетевых.** Helper уже сериализует длинные пакетные операции (очередь runner, один ответ на запрос). Сетевые операции разных туннелей должны идти параллельно: стоп одного worker не ждёт pacman. Вариант 1 смешивает эти очереди. Вариант 3 оставляет пакеты на helper, а жизненный цикл ядра — на unit (`Restart=on-failure` уже есть в `render_core_unit`).

**Peer credentials.** `src/helper/auth.rs` берёт pid и uid из `SO_PEERCRED`, не из JSON. polkit вызывается для этого процесса. Это подходит и для сетевых действий. Отдельный демон (вариант 2) обязан повторить ту же проверку, иначе Q16 не держится.

**Ownership поколений.** Сообщение несёт id поколения конфигурации. Helper отказывает, если поколение не совпало с тем, что записано для этого uid и instance. Worker не принимает поколение из чужого сокета.

**Минимальные привилегии.** Маршруты и firewall остаются у процесса с привилегией. Worker не получает `CAP_NET_ADMIN`, пока этому instance не нужен свой TUN; `render_core_unit` уже ставит capability только из `NetPrivileges`. Бинарь ядра — `CORE_BIN` (`/var/lib/cm/cores/mihomo/mihomo`), не каталог, куда ядро может писать. Legacy-юнит этот путь пока не использует; этот ADR его не меняет.

**Crash посреди транзакции.** Пакетная транзакция остаётся в helper и не считается успешной без записи. Сетевая транзакция (правила nft/ip) подтверждается только после того, как helper либо дописал правила, либо откатил их до ответа клиенту. Падение worker откатывается его unit (`Restart=on-failure`) и не держит очередь пакетов. Падение helper посреди правки firewall — явная ошибка клиенту, без «частично применено» в ответе OK.

**Q16.** Вариант 3 не опровергается, если выполнены ограничения ниже. Общий root-helper, который открывает путь из тела запроса, Q16 ломает: второй пользователь подставит каталог первого. Отдельный `cm-netd` ту же ошибку может повторить. Юнит без uid в имени позволяет одному пользователю звать systemctl чужой instance, если polkit это пустит.

## Решение

Берётся вариант 3: небольшой helper и по одному supervised systemd unit на worker.

Helper по-прежнему единственная точка polkit и `SO_PEERCRED` для привилегированных правок маршрутов и firewall. Он не становится исполнителем туннеля. Туннель — unit worker в своём namespace, как в A+C.

Вариант 1 отвергнут: сериализация пакетных операций не должна становиться сериализацией сети. Вариант 2 отвергнут как вторая реализация peer/polkit без выигрыша по Q16.

## Проверяемые последствия для I06.T01.b и дальше

1. Протокол — отдельные типизированные JSON-строки с полем версии. Это не расширение пакетного `Envelope` новыми неявными полями. Ошибка протокола — фиксированный код, без тела конфига и без чужого пути.
2. Новые действия polkit, не `io.github.cm.manage` на всё: отдельно правка маршрутов/firewall и отдельно жизненный цикл своего worker. Чужой uid в действии не подставляется из JSON.
3. Предел размера сообщения не выше нынешнего `MAX_REQUEST_BYTES` (64 КиБ) для управляющего кадра. Байты конфига ядра в этот кадр не кладутся: unit читает файл из своего каталога состояния.
4. У unit есть пользователь: `User=` равен uid peer, а не root по умолчанию. Сейчас `render_core_unit` пользователя не задаёт — это дыра, её закрывает I06, а не этот ADR кодом.
5. `StateDirectory` (или эквивалентный каталог) свой на каждый uid и instance. Имя unit содержит uid. Запрос с uid, отличным от `SO_PEERCRED`, отвергается и ничего не читает.
6. Нет операции «прочитай credentials пользователя N». Путь к хранилищу вычисляется из uid сокета. Аргумент пути в сообщении не является источником uid.
7. Кадр несёт поколение. Несовпадение — отказ, без перезапуска чужого unit.
8. Ответ OK на правку firewall возможен только после фиксации или отката. Обрыв helper в середине не выглядит успехом.
9. Worker не вызывает systemctl и не открывает сокет helper другого пользователя. Остановка чужой session этим протоколом не выражается.
