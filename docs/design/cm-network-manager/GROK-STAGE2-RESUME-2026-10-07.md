## Правила

Все правила основного брифа действуют без исключений. Повторяю главные:

1. **Перед каждой сдачей — полный gate с ядром, EXIT=0, без `SKIPPED` для тестов с ядром:**
   `CARGO_TARGET_DIR=$HOME/.cache/cm-grok-target CM_TEST_MIHOMO=$HOME/.cache/cm-cores/mihomo/mihomo sh tests/check_audit.sh`
2. **Запрещено переформатировать существующие файлы.** Нельзя запускать `cargo fmt`. Нельзя запускать `rustfmt` по любому существующему файлу: `rustfmt src/main.rs` переформатирует ещё `tui.rs` и `tui/*`, а `rustfmt src/vpn/mod.rs` — все `src/vpn/*.rs`. В diff существующего файла должны быть только смысловые строки. `rustfmt` разрешён только для своих **новых** файлов (`src/core/mihomo/{api,lifecycle,policy,stats}.rs`, `src/vpn/store_source.rs`, новые тесты), и их нужно добавить в `rustfmt --check` в gate. Перед сдачей проверить `git diff --stat`. Лишнее переформатирование — отказ при ревью.
3. Сборка только с `--offline --locked`. Сборочный каталог — `~/.cache/cm-grok-target`. Временные каталоги в тестах создавать через `TempDirGuard`.
4. Запрещены установка, `systemctl`, изменения сети хоста и файлов legacy. Сетевые проверки делаются только в harness (`unshare -rn`).
5. Секреты и настоящие подписки не должны попадать в фикстуры, ошибки, `Debug`, вывод и evidence. Неподдержанное — явная ошибка. **Молча пропускать нельзя**, в том числе через `if let Ok(..)` и `let _ =`.
6. Evidence — только `summary.json` в `stage2-evidence/2026-10-07/<пакет>/`. Если проверка SKIPPED или NOT_RUN, её нельзя записывать как PASS.
7. Коммитить только по поручению пользователя. Если пункт не закрыт, писать «открыто, причина».

## Дефекты в уже написанном (исправить до сдачи)

**F — `src/vpn/store_source.rs`:**

1. **Правила издателя молча теряются.** В `overlay_store_nodes` стоит `if let Ok(policy) = policy::from_raw(…)`. Если разбор не удался, ошибка проглатывается. В `merge_host_policy` то же самое: `if let Ok(yaml)`. Нужна явная ошибка, которая откатывает переключение, или предупреждение в `StoreSwitch.warnings`. Молча пропускать нельзя.
2. **Порядок правил.** Правила издателя дописываются **в конец** legacy-`rules`, после `MATCH`. Ядро их никогда не применит. Определить порядок: правила пользователя CM, затем правила издателя, затем финальный `MATCH`. Записать решение в отчёт и покрыть тестом.
3. **Коллизии имён групп.** Группы издателя добавляются к legacy-группам без проверки имён. Совпадение имени — явная ошибка или переименование. Тест обязателен.
4. **`cm vpn store off` при активном источнике Store.** Сейчас флаг выключается, `subs.store_source` остаётся, и при следующей сборке config хост молча уходит на legacy-провайдер. Нужно одно из двух. (а) `off` отказывает, пока активен источник Store, и подсказывает `cm vpn use N`. (б) `off` сам переключает на legacy через тот же путь с откатом. Выбор записать в отчёт. То же сделать для пункта TUI.
5. **Права.** `cm vpn store on|off` должен повышать права как остальные изменяющие команды `cm vpn`. Сейчас `c.save()` вызывается напрямую.
6. **Совместимость `subs`.** Новое поле `store_source` пишется в файл подписок legacy. Проверить, что прежняя версия `cm` читает такой файл (нет `deny_unknown_fields`), и записать это в отчёт.

**E1:** путь сокета берётся только из каталога instance. Генератор обязан отклонять `external-controller-unix` из входного документа (`HOST_LISTENER_KEYS`), на это нужен тест. Peer-проверки существуют в одном экземпляре: после выноса из `vpn/core.rs` вторая копия не допускается.

**G:** `GEOIP`/`GEOSITE` в правилах издателя для worker дают `ConfigError::InvalidRule`. Для пути V.04, то есть для хоста, геоданные есть: там такие правила допустимы. Различие покрыть тестами с обеих сторон.
