# ADR: DNS туннеля приложения — встроенный резолвер ядра (I10.T01.a, I10.T02.a, I10.T03.a)

Статус: выбрано координатором 2026-10-10 по результатам проб. Отдельный DNS-процесс (forwarder) не добавляется: пробел, который бы его оправдал, пробами не найден.

## Решение

- У каждого туннеля свой резолвер — DNS ядра этого туннеля. Приложение получает `resolv.conf` с адресом `198.18.<i>.2` (он же перехватывается на TUN).
- Запрос приложения на любой другой адрес и порт 53 ядро тоже перехватывает (`dns-hijack: any:53, tcp://any:53`).
- Наружу ядро спрашивает по DoH; имена серверов DoH находит через `1.1.1.1` и `8.8.8.8` (`default-nameserver`).
- Режим по умолчанию — `redir-host`. `fake-ip` включается только политикой туннеля (`FakeIpPolicy::Allowed`).
- IPv6: политика `Block` выключает IPv6 в сети приложения. Политика `Pass` не реализована и отвечает явным отказом.
- Кэш DNS и таблица fake-ip живут в процессе ядра: у двух туннелей они разные. При смене поколения конфига CM сбрасывает оба кэша (`POST /cache/fakeip/flush`, `POST /cache/dns/flush`), а `store-fake-ip` выключен.

## Пробы

Скрипты: [tools/dns_probe_lab.sh](tools/dns_probe_lab.sh), [tools/dns_probe_lab_srv.py](tools/dns_probe_lab_srv.py). Запросы — `dig` из сети приложения на `198.18.0.2`; вышестоящий сервер — подставной, отвечает по типу запроса. Ядро mihomo 1.19.32.

| Проба | `redir-host` | `fake-ip` |
|---|---|---|
| A | настоящий адрес | адрес из `198.19.0.0/24` |
| AAAA | пустой ответ `NOERROR` | пустой ответ `NOERROR` |
| TXT, MX, SRV | ответ сервера | ответ сервера |
| HTTPS, SVCB | ответ сервера | **пустой ответ** |
| несуществующее имя | `NXDOMAIN` | **адрес из диапазона fake-ip** |
| усечённый ответ по UDP (сервер ставит TC) | ядро повторяет по TCP, клиент получает полный ответ | то же |
| запрос по TCP | ответ | ответ |
| запрос на чужой адрес (`9.9.9.9`) | ответ ядра (перехват) | ответ ядра (перехват) |
| UDP не на порт 53 (эхо) | проходит через туннель | проходит через туннель |
| запрос по IPv6-адресу | немедленный отказ, пакетов нет | то же |
| `POST /cache/fakeip/flush`, `/cache/dns/flush` | 204 | 204; выдача адресов начинается заново |

## Последствия `fake-ip`

Поэтому он не включён по умолчанию:

- несуществующее имя получает адрес; ошибка видна только при соединении;
- записи HTTPS и SVCB не возвращаются;
- приложение видит не настоящий адрес сервера.

## Что не проверено

- DoH наружу: в пробах вышестоящий сервер — простой UDP.
- Xray: пути данных для приложений у него нет ([ADR-XRAY-DATAPATH](ADR-XRAY-DATAPATH.md)), пробы I10.T02.b не выполнялись.
- IPv6 через туннель.
- DNS хоста при systemd-resolved ([ADR-HOST-FLOW](ADR-HOST-FLOW.md)).
