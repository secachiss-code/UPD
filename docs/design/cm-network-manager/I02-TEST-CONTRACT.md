# I02: контракт будущих проверок хранения

Дата исходного контракта: 2026-10-03. Уточнение 2026-10-04: пользователь разрешил последовательную кодовую работу с Luna xhigh и ревью Sol. Типы и storage реализуются по [уточнённой модели](I02-MODEL-IMPLEMENTATION-CONTRACT-2026-10-04.md) и [контракту хранения](I02-STORAGE-IMPLEMENTATION-CONTRACT-2026-10-04.md). Runtime проверки отложены до установки; кодовая очередь и runtime acceptance учитываются отдельно.

Контракт описывает проверки **I02.T04** и **I02.T05** после появления кода хранения. Сам документ не исполняет проверки; актуальное разрешение на код дано пользователем. Сеть и изменение действующих служб в этот этап не входят. Все статусы ниже заранее **NOT_RUN**.

Норма поведения — [I02-MODEL.md](I02-MODEL.md), `schema_version` 1. Sol назначил Luna исполнителем типов; T04 начинается после ревью T01–T03. Тесты до установки не запускаются. Сборка пакета и живой хост запрещены так же, как в [контракте I01](I01-TEST-CONTRACT.md).

## Допуски

Разрешённая будущая среда — disposable каталог и процесс без TUN, без правки `/etc`, `/var/lib` хоста и без сетевых запросов. Секреты в evidence запрещены: в отчёт попадают идентификаторы, поколения, коды ошибок и факт наличия credential blob, не его содержимое.

PASS возможен только у фактически исполненного сценария. Чтение этой спецификации PASS не является.

## Проверки

| ID | Сценарий | Ожидание | Статус |
|---|---|---|---|
| S01 | Создать два Source, три ApplicationDefinition и одну группу по примерам модели | Записи читаются обратно с теми же id, ссылками и `schema_version` 1. Имени продукта в определении приложения нет | NOT_RUN |
| S02 | Публичный статус Source и Session | В сериализованном публичном статусе нет credential material. `credential_ref` на blob разрешается отдельным чтением, которое в публичный статус не копируется | NOT_RUN |
| S03 | Атомарное обновление Source и его Node | Либо видны старые generation и набор узлов, либо новые. Смеси полей двух поколений нет ни при обрыве записи, ни при ошибке одного из связанных объектов | NOT_RUN |
| S04 | Замена используемого узла | Пока Session или HostPolicy ссылается на Node, запись другого Node под тем же id отклоняется. Ошибка называет ссылку. Случайный узел не подставляется | NOT_RUN |
| S05 | Удаление используемого Source | Удаление отклоняется, пока есть ConnectionProfile, HostPolicy, группа или Session со ссылкой. После снятия ссылок и завершения сессий удаление удаляет и credential blob | NOT_RUN |
| S06 | Staged removal | Промежуточное состояние «ссылки сняты, blob ещё есть» читается явно. Повтор того же плана не создаёт второй blob и не возвращает удалённый id | NOT_RUN |
| S07 | Restart процесса хранилища | Живая по смыслу Session, записанная до restart, читается с прежними `tunnel_instance_id` и `tunnel_generation` | NOT_RUN |
| S08 | Два одновременных обновления одного Source | Итог — одно целое поколение либо отказ обоих. Набор узлов не собирается из частей двух записей | NOT_RUN |
| S09 | Узел исчез в новом поколении Source | Старая Session хранит прежнюю generation. Её Verification NET становится `blocked` или `error` с временем evidence. Новый узел того же источника ей молча не назначается | NOT_RUN |
| S10 | Stop host | HostPolicy становится off, туннель хоста остановлен в модели записей. Session приложений и их generation остаются | NOT_RUN |
| S11 | Общая группа | Завершение Session одного из двух приложений группы оставляет вторую Session и не меняет HostPolicy | NOT_RUN |
| S12 | Ось Verification | Запись `verified` в NET оставляет REGION, STATE и APP в `unknown`, если их отдельно не записывали | NOT_RUN |
| S13 | Чужая `schema_version` | Запись версии, отличной от 1, не читается как версия 1 и не переписывается молча | NOT_RUN |

## При провале

Любой провал S03, S04, S08 или S09 блокирует приёмку I02. Хранилище, которое подменяет используемый узел или смешивает поколения, downstream-направления не принимают. Исправление — новая ревизия evidence, не отметка PASS поверх старого прогона.

До первого исполненного прогона runtime acceptance I02.T04 и I02.T05 остаётся открытой. После завершения и ревью кода T04/T05 можно последовательно продолжать разрешённую кодовую очередь; это не разрешение на эксплуатацию или отметка PASS.
