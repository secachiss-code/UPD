## Правила для Grok на весь план

- Исполнитель — Grok 4.7 (high), ревью — координатор. Подзадача закрыта только после ревью; для P0-рубежей (I06–I10) и отмеченных задач — полное ревью и финальное P0-ревью в свежем контексте.
- Брать только подзадачи, у которых закрыты все зависимости. Порядок внутри этапа — по столбцу «зависит от».
- Перед сдачей: `tests/check_audit.sh` зелёный, фактический прогон записан в evidence (summary + хеши, сырые логи — по D8).
- Сборка и тесты в своём `CARGO_TARGET_DIR`. Сеть — только чтение первичных источников pinned-версий и разрешённые `cargo fetch`. Никаких реальных подписок и секретов; fixtures синтетические.
- Установка, службы, изменение сети хоста, внешние публикации, коммиты и push — только по поручению пользователя. L2-проверки — в среде harness (D6), L3/L4 на хосте — по поручению (D10).
- Не переформатировать существующие файлы: никаких `cargo fmt` и `rustfmt` по старым файлам (`rustfmt src/main.rs` форматирует и все его модули). В diff — только смысловые строки; rustfmt — только по своим новым файлам. Лишнее переформатирование — отказ при ревью.
- Неподдержанное — явный Unsupported, не молчаливое удаление. Секреты не попадают в ошибки, `Debug`, статус и evidence.
- Решения пользователя Grok не выбирает: готовит материалы и останавливает зависимые подзадачи.
