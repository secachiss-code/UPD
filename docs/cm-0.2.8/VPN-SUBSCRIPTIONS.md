# VPN-подписки в CM 0.2.8

Проверены исходники серверов подписок:

- [Marzban: маршрутизация подписки](https://github.com/Gozargah/Marzban/blob/master/app/routers/subscription.py): распознаёт mihomo, ClashMeta, Clash-Verge и FlClash как clash-meta; старый v2rayNG получает список ссылок в base64.
- [Remnawave: стандартные правила ответа](https://github.com/remnawave/templates/blob/main/remnawave-default/response-rules/srr-default-config.json): отдельные группы клиентов Mihomo, Clash и Sing-box, HTML по Accept и запасной ответ XRAY_BASE64.

CM сначала пробует User-Agent из настроек подписки, если задан. Затем, без
повторов, пробует mihomo/1.19.32, ClashMeta/1.19.32, Clash-Verge/2.4.2,
FlClash/0.8.92 и v2rayNG/1.8.10. Поддерживаются YAML Clash/mihomo и списки
URI в тексте или base64. Sing-box/Xray JSON не выдаются за профиль mihomo.
Повтор выполняется только после успешного HTTP-ответа с непригодным телом:
заглушкой, HTML или неподдерживаемым форматом. Ошибки сети и HTTP прекращают
попытки. Адрес и токен остаются у исходного провайдера; внешнего конвертера нет.
Заголовки трафика, интервала и названия принимаются только из успешного ответа.
Сохранённый ранее непригодный профиль заново загружается при `cm vpn use`.

Тесты проверяют цепочку заглушка → HTML → YAML, успешный base64, конечное
число попыток и остановку на HTTP 403. Подписка из сообщения пользователя
не проверялась на реальном сервере: её адрес не предоставлен. Настроенные
провайдером ограничения устройств/клиентов могут требовать его поддержки.
