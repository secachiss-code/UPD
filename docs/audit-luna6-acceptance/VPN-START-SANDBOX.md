# Повторная ошибка запуска VPN — 2026-10-01

Установленный `/usr/local/bin/upd` совпадал по SHA-256 с последним release CLI. В журнале `upd-vpn.service` подготовка завершалась с `Read-only file system (os error 30)`, затем повторные запуски приводили к `start-limit-hit`.

Причина: `write_config` открывал `/var/lib/upd/.vpn-config.lock`, но unit с `ProtectSystem=strict` разрешает запись только в `/var/lib/upd/vpn`. Блокировка перенесена в каталог VPN для всех писателей: CLI, helper, сохранения настроек и подготовки службы. Ограничения unit сохранены. Ошибки открытия блокировки теперь содержат путь. Каталог и новые файлы блокировки создаются с правами 0700 и 0600.

Проверки:

- Полный `RUST_TEST_THREADS=1 sh tests/check_audit.sh`: 151 lib + 47 CLI + 24 integration + 33 COSMIC + 4 packaging = 259 тестов, успешно.
- Регрессия `vpn_config_lock_needs_only_writable_vpn_home`: VPN-блокировка работает и сериализует писателей при недоступном родительском state; обычная блокировка state ожидаемо не работает.
- Проверка через bubblewrap с доступным для записи только тестовым каталогом VPN, изолированными процессами и сетью: установленный бинарник воспроизводит ошибку read-only; исправленный debug CLI успешно выполняет `vpn prepare`. Используются тестовый профиль и фиктивное ядро, реальные подписки не читаются, VPN не запускается.
- Воспроизводимая проверка: `python3 tests/check_vpn_sandbox.py target/x86_64-unknown-linux-musl/debug/upd`.

На машине пользователя работает внешний FlClash; его процессы и соединение не изменялись. Реальный запуск `upd-vpn` не выполнялся. Установка исправления не выполнялась; `sudo -n` требует пароль. По последнему указанию пользователя release-бинарники не собирались.
