# Проверка ошибок при работе — 2026-10-01

После сообщения пользователя об ошибке проверены установленные бинарники,
состояние systemd helper и пути исполняемых файлов работающих апплетов.
SHA-256 установленных CLI/COSMIC совпадали с release-сборкой, но helper
работал с 2026-09-29. Его read-only `hello` отвергался как неизвестная команда,
а `status` не содержал protocol_version и показывал running=false.
Оба работающих апплета ссылались на `/usr/local/bin/upd-cosmic (deleted)`.

Исправлены следующие ошибки:

1. Установщик включал socket, но оставлял активный helper на прежнем бинарнике.
   После установки простаивающий helper синхронно перезапускается через
   `systemctl try-restart upd-helper.service`; ошибка возвращается пользователю.
   Если helper ведёт операцию (включая обновление самого upd через пакетный
   менеджер), перезапуск пропускается с явным сообщением о ручном перезапуске
   после завершения. Installer-only read-only Status поддерживает старый helper
   без Hello; обычные mutation-запросы сохраняют строгую проверку протокола.
   Regression fixture проверяет порядок после enable, отказ systemctl и
   сохранение работающей операции по legacy Status.
2. Повторное подключение к той же операции игнорировало весь replay. Теперь
   журнал, этап, вопрос и завершение восстанавливаются в отдельном bounded
   OpView и применяются на ReplayComplete. Прокрутка сохраняется; ответ
   сохраняется только для того же prompt_id. Проверены пропущенный вывод,
   ненулевой exit, отсутствие дублирования истории и смена вопроса.
3. Reset другой операции игнорировался, если окно уже знало предыдущую.
   Теперь Reset в текущем поколении подписки переключает окно на новую
   операцию; старые Exit и callbacks по-прежнему отбрасываются.
4. После atomic replacement апплет запускал окно по пути с Linux-суффиксом
   `(deleted)`. Теперь он запускает существующий новый бинарник в том же
   каталоге. Fixture проверяет реальный запуск и передачу аргументов, а также
   ошибку при отсутствии замены.
5. После начальной ошибки helper окно и апплет не повторяли запрос состояния
   во время простоя. Теперь повтор выполняется через Jobs с прежним backoff;
   апплет действительно проверяет helper при повторе. Две проверки показывают
   восстановление idle GUI после первоначальной ошибки.

Дополнительно исправлено нестабильное измерение ресурсов в attach fixture:
появление socket ещё не означает завершения backend detection, которое
временно открывает os-release. Исходный замер иногда получал 5 FD, итоговый —
4 FD и ложно падал. Теперь fixture ждёт строгое idle-состояние: один поток,
три stdio FD и listener. Проверка возврата ресурсов остаётся строгой.

Реальный перезапуск helper не выполнен: `sudo -n systemctl try-restart
upd-helper.service` потребовал пароль. Пользователю передана команда
`sudo systemctl restart upd-helper.service`. Запущенные старые апплеты также
требуют перезапуска через панель COSMIC; изменения исходников не обновляют
память уже работающих процессов. Интерактивное устранение сообщённой ошибки
на установленной системе пока не подтверждено пользователем.

Финальный `./tests/check_audit.sh` прошёл: 149 lib + 42 CLI + 24 integration +
30 COSMIC + 4 packaging = 249 тестов. Production debug builds, renderer smoke,
shell syntax и scoped rustfmt также прошли. [Журнал](RUNTIME-GATE.log).

После финального gate выполнен `CARGO_NET_OFFLINE=true ./build.sh`: успешно
собраны release CLI musl и COSMIC GNU версии 0.2.7. Проверены `--version`
обоих ELF. Бинарники находятся в `dist/upd-linux-amd64` и
`dist/upd-cosmic-linux-amd64`; установленная копия пока не заменена.
