# Маршрут исполнения

Это план по дереву на 2026-09-25. Исходники не изменялись. Сначала читать [FIX_DAG.md](FIX_DAG.md) или [TEST_DAG.md](TEST_DAG.md), затем **только файл очередной готовой вершины** из `fix/` или `test/`. После выполнения вершины отметить её в журнале исполнения и переходить к следующей, чьи зависимости закрыты. Таблицы в главных файлах содержат все вершины, поэтому предварительно открывать остальные детали не нужно.

«Подтверждено» означает, что механизм непосредственно виден в текущем коде. «Условно» означает, что путь исполнения подтверждён, а эксплуатационный эффект зависит от внешней программы, окружения или действий пользователя. Статическая проверка не подменяет испытание на целевых дистрибутивах. Для FS-01 не утверждается, что локальная атака через symlink уже воспроизведена. Для META-01 нельзя самостоятельно объявить лицензию от имени правообладателя.

**Итог перепроверки:** кодовая основа всех 31 записей `BUGS.md` подтверждена; полностью опровергнутых записей нет. Уточнены пределы утверждений для FS-01, SEC-05, UPD-04, NET-03, SYS-02 и META-01 в главном DAG и соответствующих detail-файлах. Дополнительная проверка смежного кода выявила ещё пять отдельных проблем. Исполнение на реальных системах в эту проверку не входило.

Составные записи `BUGS.md` разбиты на узкие вершины: SEC-04, UPD-02, UPD-04 и SPACE-01. В них одна вершина отвечает за один наблюдаемый дефект и один итоговый контракт, хотя исправление может затронуть много строк.

## Общие правила для исполнителей

1. Перед изменением очередной вершины прочитать её detail-файл и указанные там соседние участки; проверить, что строковые якоря ещё актуальны.
2. Для операций над системными путями использовать изолированный тестовый каталог/моки. Не запускать реальное обновление пакетов, firmware, управление чужими службами или запись в `/etc` ради теста.
3. Сохранять ошибку и прежнее рабочее состояние при частичном отказе. Не считать пустой список доказательством успешной проверки, если источник сообщил ошибку.
4. После каждой вершины записать фактические изменения, результаты соответствующего контракта и обнаруженные отклонения. Зависимые вершины открывать только после этого.

## Проверенные смежные цепочки

- `ureq::Error` в закреплённой версии `2.12.1` печатает URL при HTTP-статусе и транспортной ошибке; `vpn::get` превращает это в строку, `update_subs` сохраняет её, `publish_state` копирует в `vpn.json`, `save_json` ставит `0644`. Проверены `Cargo.lock` и локальный исходник `ureq`.
- `gather` сохраняет ошибку получения пакетов, но `cmd_update` проверяет лишь один её текст; `cmd_auto` заканчивается нулём. Отдельно `zypper` и дополнительные источники скрывают собственные ошибки до `gather`.
- `delete_sub` удаляет профиль до сохранения JSON; CLI пропускает `apply`, когда список стал пустым. Параллельные VPN-команды обходят `with_lock`; `load_subs` смешивает отсутствие файла с повреждением.
- Для APT подтверждены три соседних риска: публичная резервная копия, потеря прав исходного файла и нетранзакционный перевод на `mirror+file:`. Изменять эти ветки нужно согласованно.
