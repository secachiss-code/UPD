## Волна 2 — сопоставление заявлений с реализацией

Анализ проведён до правок этой волны, по исходникам и соседним ветвям вызова:

1. **`UPD-03/04`, подтверждён остаточный дефект.** `Config::defaults` включает Flatpak, а `extras::flatpak_updates` трактует отсутствие необязательной команды как ошибку. Поэтому `upd auto` завершится кодом 1 на системе без Flatpak. Сам сбой `flatpak remote-ls` после запуска должен оставаться ошибкой. Исправить различение «не установлен / проверка не удалась» и проверить обе ветви.
2. **`UPD-03/04`, подтверждён остаточный дефект.** `upd check` возвращает код по `st.error`, игнорируя `flatpak_error` и `firmware_error`. `upd update` при отсутствии доступных пакетов сообщает о непроверенных источниках, но тоже возвращает 0. Исправить общую проверку статуса и код выхода; ошибки опциональных источников после реальной установки также должны попасть в итог.
3. **`NET-04/UPD-03`, подтверждён остаточный дефект.** `cmd_auto` печатает ошибку применения зеркал и продолжает, а затем может вернуть 0. Сохранить возможность проверить пакеты, но завершать задачу с ошибкой зеркал.
4. **`APT-01/02`, подтверждён остаточный дефект.** `cmd_uninstall` игнорирует `remove_mirrors()` и печатает «upd удалён», даже если восстановление APT-конфигурации не удалось. Исправить порядок и код выхода. Пакетный сценарий отдельно глотает ошибку через `|| true`; полную гарантию восстановления для пакетного удаления заявлять нельзя.
5. **VPN-правила, дополнительный подтверждённый дефект.** `vpn::user_rules` игнорирует ошибку создания файла и возвращает пустой список при ошибке чтения. `build_config` тогда может записать конфигурацию без пользовательских правил. Сделать чтение результатом `Result` и прервать сборку при ошибке; в TUI показывать ошибку.
6. **`SEC-01`, заявленные тесты на этой машине не прошли.** Два теста требуют TCP bind; один из них использует HTTP URL, который теперь отклоняется до сетевой ошибки. Заменить их независимыми от сокетов тестами реальной очистки ошибок и ветви подписки. Тесты `UPD-02A/B` и `UPD-03` в `main.rs` повторяют собственную логику вместо вызова рабочего кода; `VPN-03` вызывает настоящий `systemctl`. Привязать тесты к чистым функциям, которые использует приложение, и исключить побочное действие.
7. **Документация расходится с кодом.** `SEC-02` теперь требует SHA-256, но README и архитектура обещают продолжение без digest. Архитектура также описывает старое условие повторного замера зеркал и один старый TUI-тест. Исправить описания после ремонта.
8. **`META-01` не закрыта.** nfpm заявляет MIT при отсутствии файла лицензии и утверждения правообладателя. Лицензию нельзя выбрать по результатам технического аудита; не отмечать эту вершину выполненной и не добавлять вымышленный текст лицензии.

Границы проверки: успешное выполнение 65 тестов само по себе не доказывает работу системных транзакций APT/pacman, systemd и сети. Эти ветви требуют отдельной интеграционной проверки в подходящем окружении.

## Волна 3 — выполненные мной исправления

- Отсутствующий необязательный Flatpak теперь пропускается без ошибки; ненулевой код `flatpak remote-ls` остаётся ошибкой. Добавлен тест обеих ветвей.
- `upd check` учитывает ошибки Flatpak и прошивок. `upd update` возвращает ошибку, если дополнительные источники не проверены даже при пустом списке, а также после частично успешного обновления; ошибка сохранения итогового состояния больше не скрывается.
- `upd auto` после ошибки применения зеркал продолжает проверку пакетов, но завершает задачу с кодом 1. Существующая логика ошибок фонового состояния вынесена в используемую командой функцию и проверяется тестами.
- `upd uninstall` сначала восстанавливает зеркала и при неудаче прерывает удаление с кодом 1. Для пакетного сценария `preremove.sh` по-прежнему использует `|| true`: пакетный менеджер может продолжить удаление, даже если восстановление не прошло.
- Чтение пользовательских VPN-правил теперь возвращает ошибку ввода-вывода; сборка конфига и редактор останавливаются, TUI показывает ошибку. Добавлены проверки чтения файла и ошибки чтения.
- SEC-01 тесты больше не требуют TCP bind. Они проверяют сокрытие секрета в ошибках статуса, транспорта, сохранённом состоянии и при отклонении URL подписки. Тест сообщения о сбое перезапуска больше не вызывает реальный `systemctl`; тесты обработки ошибок обновления используют функции, вызываемые рабочим кодом.
- README и описание архитектуры приведены в соответствие с обязательной SHA-256 проверкой и текущим повторным замером зеркал.

Проверка после правок: `cargo test --offline` — **70 passed / 0 failed**; `git diff --check` — успешно. `cargo fmt --check` не был основанием для массового форматирования: он не проходил и до этой волны. Проверки реальных пакетных транзакций, сетевых ответов и systemd в этом окружении не проводились; прежние отметки ✓ в DAG сами по себе не подтверждают такие сценарии. `META-01` остаётся открытой до решения правообладателя.
