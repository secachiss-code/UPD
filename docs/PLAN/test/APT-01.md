# Контракт APT-01 — Сохранять поздние изменения APT при удалении upd?

**Предусловия:** исправление [fix/APT-01](../fix/APT-01.md) завершено; зависимости: [SEC-04C](../test/SEC-04C.md), [APT-02](../test/APT-02.md). Использовать собственный изолированный fixture.

## Подготовка входа

Изолированное дерево APT в tmpdir с файлами разных mode/owner; ошибки записи вводить на каждом переходе через файловый адаптер. Сравнить байты и права до/после.

**Наблюдаемая граница:** src/backend.rs:531–540 сохраняет исходный текст, 557–563 целиком восстанавливает старую копию без сравнения текущего файла.

## Развилка принятия / корректности

1. **Положительная ветвь:** Добавленная администратором stanza после apply остаётся после remove; неизменённый файл восстанавливается точно; конфликт отмечается без потери данных.
2. **Отрицательная ветвь:** Если поздняя строка исчезает без предупреждения или backup удаляется после отказа restore, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.

**После закрытия:** отметить контракт в [тестовом DAG](../TEST_DAG.md).
