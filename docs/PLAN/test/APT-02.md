# Контракт APT-02 — Делать переход APT на mirror+file восстановимым?

**Предусловия:** исправление [fix/APT-02](../fix/APT-02.md) завершено; зависимости: [SEC-04A](../test/SEC-04A.md), [SEC-04B](../test/SEC-04B.md), [SEC-04C](../test/SEC-04C.md). Использовать собственный изолированный fixture.

## Подготовка входа

Изолированное дерево APT в tmpdir с файлами разных mode/owner; ошибки записи вводить на каждом переходе через файловый адаптер. Сравнить байты и права до/после.

**Наблюдаемая граница:** src/backend.rs:531–555: backup/source файлы меняются по очереди, список зеркал пишется в конце, rollback нет.

## Развилка принятия / корректности

1. **Положительная ветвь:** Инъекция ошибки после каждого шага оставляет либо старую конфигурацию, либо полностью рабочую новую; apt source никогда не ссылается на отсутствующий список после завершения.
2. **Отрицательная ветвь:** Если после отказа остаётся ссылка на несуществующий/неподходящий APT_LIST, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.

**После закрытия:** отметить контракт в [тестовом DAG](../TEST_DAG.md).
