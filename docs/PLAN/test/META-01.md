# Контракт META-01 — Согласовать лицензионные метаданные с правообладателем?

**Предусловия:** исправление [fix/META-01](../fix/META-01.md) завершено; зависимости: —. Использовать собственный изолированный fixture.

## Подготовка входа

Статическая проверка фактического LICENSE, Cargo.toml, nfpm и README после подтверждённого решения правообладателя; тест не должен назначать лицензию.

**Наблюдаемая граница:** packaging/nfpm.yaml:14 содержит license: MIT; Cargo.toml не содержит license; в текущем дереве нет LICENSE/COPYING.

## Развилка принятия / корректности

1. **Положительная ветвь:** LICENSE, Cargo.toml, nfpm и README согласованы с подтверждённым решением правообладателя; получатель исходников видит текст лицензии.
2. **Отрицательная ветвь:** Если MIT остаётся только в nfpm или добавлен без подтверждения права на публикацию, контракт не закрыт.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.
