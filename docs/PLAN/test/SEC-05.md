# Контракт SEC-05 — Удалять управляющие символы из названия профиля?

**Предусловия:** исправление [fix/SEC-05](../fix/SEC-05.md) завершено; зависимости: [PARSE-01](../test/PARSE-01.md). Использовать собственный изолированный fixture.

## Подготовка входа

Локальный HTTP-ответ/fixture, без внешней сети; подменить заголовки, тело, статус, redirect и ошибку транспорта. Секрет-маркер искать в каждом выходном канале.

**Наблюдаемая граница:** src/vpn.rs:270–281, 332–337, 429–445; src/main.rs:552; src/tui.rs:793.

## Развилка принятия / корректности

1. **Положительная ветвь:** Имя из заголовка с ESC/newline отображается одной безопасной строкой, с обычной кириллицей отображается без искажения.
2. **Отрицательная ветвь:** Если терминал получает управляющий байт или имя распадается на строки, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.

**После закрытия:** отметить контракт в [тестовом DAG](../TEST_DAG.md).
