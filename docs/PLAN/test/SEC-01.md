# Контракт SEC-01 — Исключить URL подписки из ошибок?

**Предусловия:** исправление [fix/SEC-01](../fix/SEC-01.md) завершено; зависимости: —. Использовать собственный изолированный fixture.

## Подготовка входа

Локальный HTTP-ответ/fixture, без внешней сети; подменить заголовки, тело, статус, redirect и ошибку транспорта. Секрет-маркер искать в каждом выходном канале.

**Наблюдаемая граница:** src/vpn.rs:168–187, 367–391, 429–445; src/common.rs:354–360; Cargo.lock: ureq 2.12.1. В ureq/src/error.rs:210–238 Display печатает URL, включая redirect origin.

## Развилка принятия / корректности

1. **Положительная ветвь:** HTTP 401 и DNS-ошибка для URL с userinfo, token path/query и redirect показывают код/категорию; секрет отсутствует в stdout, журнале, subs.error и публичном vpn.json.
2. **Отрицательная ветвь:** Если токен появляется в любом из четырёх каналов, контракт нарушен. Если ошибка скрыта полностью, проверить диагностическую полезность кода/категории.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.
