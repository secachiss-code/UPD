# Контракт DATA-03 — Сохранять профиль до удаления старого?

**Предусловия:** исправление [fix/DATA-03](../fix/DATA-03.md) завершено; зависимости: [DATA-01](../test/DATA-01.md), [DATA-02](../test/DATA-02.md). Использовать собственный изолированный fixture.

## Подготовка входа

Изолированные UPD_VPN_ETC/UPD_VPN_HOME/UPD_STATE_DIR; контролируемые параллельные процессы или барьеры; systemctl подменить скриптом, записывающим вызовы.

**Наблюдаемая граница:** src/vpn.rs:285–291 удаляет оба старых расширения до write_private; delete_sub:347–355 удаляет профиль до save_subs.

## Развилка принятия / корректности

1. **Положительная ветвь:** Инъекция ENOSPC на каждом write сохраняет прежний профиль и прежнюю запись подписки; успешное удаление не оставляет активной ссылки на удалённый профиль.
2. **Отрицательная ветвь:** Если ошибка записи оставляет JSON со старой записью и без старого файла, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.

**После закрытия:** отметить контракт в [тестовом DAG](../TEST_DAG.md).
