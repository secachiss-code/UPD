# Контракт NET-01 — Учитывать IPv6 default route в отпечатке сети?

**Предусловия:** исправление [fix/NET-01](../fix/NET-01.md) завершено; зависимости: —. Использовать собственный изолированный fixture.

## Подготовка входа

Зафиксированные снимки /proc, /sys и каталогов модулей через выделенный parser с инъекцией пути; проверить обе файловые раскладки.

**Наблюдаемая граница:** src/common.rs:589–615 читает только /proc/net/route; src/mirrors.rs:323–333 пропускает обработку при online=false.

## Развилка принятия / корректности

1. **Положительная ветвь:** IPv6-only default route даёт online=true и стабильный id; изменение gateway меняет id и запускает обработку сети; отсутствие маршрута даёт offline.
2. **Отрицательная ветвь:** Если IPv6-only система отмечена offline или разные шлюзы имеют один id, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.
