# Контракт UPD-02A — Учитывать ошибку установки Flatpak в результате update?

**Предусловия:** исправление [fix/UPD-02A](../fix/UPD-02A.md) завершено; зависимости: [UPD-04A](../test/UPD-04A.md). Использовать собственный изолированный fixture.

## Подготовка входа

Fake Backend и заглушки внешних команд с управляемыми stdout, stderr и exit status; сетевые ответы отдавать локальным сервером. Проверять и возвращаемое состояние, и код CLI.

**Наблюдаемая граница:** src/main.rs:322–324, 331–347: flatpak_upgrade Err только печатается, состояние целиком очищается.

## Развилка принятия / корректности

1. **Положительная ветвь:** При успешном system upgrade и ошибке Flatpak команда возвращает ненулевой код, оставляет информацию о неустановленных Flatpak обновлениях; при полном успехе очищает их.
2. **Отрицательная ветвь:** Если вывод «Обновление завершено»/exit=0 скрывает ошибку Flatpak или список исчезает, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.

**После закрытия:** отметить контракт в [тестовом DAG](../TEST_DAG.md).
