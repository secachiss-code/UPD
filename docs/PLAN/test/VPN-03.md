# Контракт VPN-03 — Сообщать об ошибке перезапуска после обновления ядра?

**Предусловия:** исправление [fix/VPN-03](../fix/VPN-03.md) завершено; зависимости: [SEC-02](../test/SEC-02.md). Использовать собственный изолированный fixture.

## Подготовка входа

Изолированные UPD_VPN_ETC/UPD_VPN_HOME/UPD_STATE_DIR; контролируемые параллельные процессы или барьеры; systemctl подменить скриптом, записывающим вызовы.

**Наблюдаемая граница:** src/main.rs:638–646: CLI core update/reinstall игнорирует vpn::restart Err и возвращает успех core_install; src/vpn.rs:1108–1117: maintain сохраняет событие об обновлении, затем игнорирует restart Err.

## Развилка принятия / корректности

1. **Положительная ветвь:** При успешной замене и неудачном restart CLI возвращает ошибку, фоновое состояние показывает проблему; при успешном restart версия активного процесса соответствует установленной.
2. **Отрицательная ветвь:** Если команда возвращает 0 или событие говорит об активном обновлении при failed restart, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.
