# Контракт NET-04 — Подтверждать смену сети только после применения зеркал?

**Предусловия:** исправление [fix/NET-04](../fix/NET-04.md) завершено; зависимости: [NET-02](../test/NET-02.md). Использовать собственный изолированный fixture.

## Подготовка входа

Fake Backend и заглушки внешних команд с управляемыми stdout, stderr и exit status; сетевые ответы отдавать локальным сервером. Проверять и возвращаемое состояние, и код CLI.

**Наблюдаемая граница:** src/mirrors.rs:235–262 записывает best/fingerprint/checked до apply_mirrors; apply_mirrors:282–304 возвращает false при ошибке записи; check_mirrors:261 игнорирует результат; handle_network:332–335 затем считает id уже обработанным.

## Развилка принятия / корректности

1. **Положительная ветвь:** При ошибке записи mirrorlist состояние сохраняет pending/error, следующий net повторяет применение; при успехе id отмечается применённым и повтор не нужен.
2. **Отрицательная ветвь:** Если после ошибки записи следующий net выводит «сеть та же» и не повторяет попытку, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.
