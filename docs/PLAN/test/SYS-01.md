# Контракт SYS-01 — Разбирать service cgroup v1?

**Предусловия:** исправление [fix/SYS-01](../fix/SYS-01.md) завершено; зависимости: —. Использовать собственный изолированный fixture.

## Подготовка входа

Зафиксированные снимки /proc, /sys и каталогов модулей через выделенный parser с инъекцией пути; проверить обе файловые раскладки.

**Наблюдаемая граница:** src/common.rs:825–831: ищется лишь строка 0::; v1 использует контроллерные строки.

## Развилка принятия / корректности

1. **Положительная ветвь:** Fixture 0::/system.slice/x.service и 1:name=systemd:/system.slice/x.service дают одинаковый unit; пользовательский процесс не попадает в системные службы.
2. **Отрицательная ветвь:** Если v1 запись игнорируется, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.

**После закрытия:** отметить контракт в [тестовом DAG](../TEST_DAG.md).
