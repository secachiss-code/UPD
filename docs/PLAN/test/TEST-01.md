# Контракт TEST-01 — Сделать TUI тест детерминированным?

**Предусловия:** исправление [fix/TEST-01](../fix/TEST-01.md) завершено; зависимости: —. Использовать собственный изолированный fixture.

## Подготовка входа

Запуск теста с пустым PATH для пакетных менеджеров и fixture состояния; намеренно поменять ожидаемый текст/переход, чтобы убедиться, что assertion падает.

**Наблюдаемая граница:** src/tui.rs:1005–1035: единственный #[test] вызывает backend::detect().unwrap(), gather_status, vpn::snapshot и только печатает экраны.

## Развилка принятия / корректности

1. **Положительная ветвь:** Тест одинаково проходит без пакетного менеджера, сети и VPN и падает при изменении ожидаемого текста/перехода.
2. **Отрицательная ветвь:** Если тест проходит без assertions или требует реальный host backend, контракт нарушен.
3. **Решение:** обе ветви совпали с ожиданием — контракт принят; любая не совпала — контракт отклонён с минимальным воспроизводимым входом и фактическим выводом; fixture не запустился — статус «не проверен».

## Что сохранить как доказательство

Записать команду адресного теста, ожидаемый/фактический exit status, состояние файлов/JSON и короткий вывод. Для условного эффекта отделять подтверждение кода от испытания на конкретной ОС или версии утилиты.
