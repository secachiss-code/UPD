## Порядок выполнения

Выбрать первую готовую вершину по таблице, открыть только её файл, внести исправление и передать тестовому агенту соответствующий контракт. При неуспехе контракта вернуть вершину на исправление. Ветки без зависимости допускают перестановку, но одна вершина всегда завершает одно наблюдаемое поведение.

## Уточнения исходного аудита

- `FS-01`: подтверждён предсказуемый путь и передача его root-утилите; успешная symlink-атака не доказана. Исправление убирает ненужную предпосылку для гонки.
- `UPD-04C`: AUR проверяется в интерактивном `cmd_update`; в `gather` и `auto` его нет. Формулировка исходной сводки про все дополнительные источники требует этого ограничения.
- `NET-03`: исправление через безусловный порог 256 КиБ было бы неверным для законно маленького APT InRelease; нужна проверка ответа.
- `SEC-02`: digest из того же API подтверждает целостность загрузки относительно метаданных, но не даёт независимого подтверждения происхождения при компрометации самого API.
- `META-01`: владелец проекта подтвердил MIT в диалоге 2026-09-26; лицензия оформлена в репозитории и пакете.
