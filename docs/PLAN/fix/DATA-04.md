# DATA-04 — Сохранять существующий конфиг при ошибке чтения?

**Оценка:** подтверждено для read_to_string error. **Источник:** дополнительная перепроверка смежного кода; в `docs/BUGS.md` записи нет.

**Перед началом:** закрыты —. Открыть только этот detail; перепроверить строковые якоря.

## Проверка смежных участков

src/common.rs:144–151: Config::load возвращает defaults при любой ошибке read_to_string; src/main.rs:73–76 и многочисленные TUI/CLI ветки затем вызывают Config::save, переписывая /etc/upd.conf.

## Правка

Сделать Config::load fallible: только NotFound при первичной установке допускает defaults; EACCES, I/O и невалидный UTF-8 возвращают ошибку. Передать Result всем вызывающим веткам; mutating commands и TUI отказываются сохранять конфиг, если чтение существующего файла не удалось. Не создавать новый default поверх повреждённого. Сообщать путь и причину.

## Готово, когда

Отсутствующий файл в первый запуск получает defaults; существующий файл с I/O/UTF-8 ошибкой сохраняет исходные байты и выдаёт ошибку, даже при попытке изменить один параметр.

## Ограничение / риск

Сохранить поведение соседних веток, особенно обработку отказа и уже записанное состояние.
