# NET-03 — Проверять короткий успешный ответ зеркала?

**Оценка:** подтверждено, но универсальный порог 256 КиБ неприменим к малым корректным файлам. **Источник:** `docs/BUGS.md`, запись `NET-03`.

**Перед началом:** закрыты —. Открыть только этот detail; перепроверить строковые якоря.

## Проверка смежных участков

src/mirrors.rs:42–68: PROBE_MIN проверяется только при timeout; на EOF достаточно n>0. Backend::probe_url для apt может указывать на законный небольшой InRelease.

## Правка

В probe_speed после EOF проверять ожидаемый размер через Content-Length/Content-Range и статус 206; для полного 200 ответа валидировать тип/структуру контрольного файла согласно backend (pacman db или APT InRelease) либо вынести в backend::validate_probe. Не объявлять любой ответ меньше PROBE_MIN нерабочим: это сломает небольшие настоящие InRelease. Captive portal HTML должен отвергаться до ранжирования скорости.

## Готово, когда

Короткий HTML 200 отвергается; корректный небольшой APT InRelease принимается; обрезанный относительно Content-Length ответ отвергается.

## Ограничение / риск

Сохранить поведение соседних веток, особенно обработку отказа и уже записанное состояние.
