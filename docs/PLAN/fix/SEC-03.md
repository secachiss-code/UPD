# SEC-03 — Запретить незашифрованные URL подписок?

**Оценка:** подтверждено. **Источник:** `docs/BUGS.md`, запись `SEC-03`.

**Перед началом:** закрыты [SEC-01](../fix/SEC-01.md). Открыть только этот detail; перепроверить строковые якоря.

## Проверка смежных участков

src/vpn.rs:322–324, 263; docs/ARCHITECTURE.md указывает поддержку HTTP.

## Правка

В add_sub заменить starts_with("http://") || starts_with("https://") на разбор URL с допустимой схемой https и проверкой корректного host; в fetch_sub/get защищать уже сохранённые HTTP-подписки отказом с понятной ошибкой. Для подписок отключить автоматические редиректы ureq (AgentBuilder::redirects(0)) и вручную разрешать только https Location с ограничением числа переходов. Описать миграцию и новый контракт в README/docs/CONFIGURATION.md.

## Готово, когда

Новый HTTP URL отвергается до запроса; старый HTTP URL не обновляется; HTTPS работает с редиректами только на HTTPS.

## Ограничение / риск

Проверить политику HTTP-редиректов ureq; запрещать downgrade до сетевого запроса.
