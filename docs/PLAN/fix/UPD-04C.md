# UPD-04C — Отличать сбой проверки AUR от пустого списка?

**Оценка:** подтверждено только для интерактивного update. **Источник:** `docs/BUGS.md`, запись `UPD-04`.

**Перед началом:** закрыты [UPD-01](../fix/UPD-01.md). Открыть только этот detail; перепроверить строковые якоря.

## Проверка смежных участков

src/extras.rs:41–48: aur_updates берёт stdout без exit; src/main.rs:260–265 вызывает это в cmd_update. В gather/auto AUR вообще не проверяется: это уточнение к BUGS.md.

## Правка

Изменить aur_updates(user) на Result<Vec<String>, String> с проверкой exit и разбора. В cmd_update отображать сбой AUR как ошибку источника и не объявлять систему обновлённой при неизвестном результате. Отдельно решить, должен ли auto проверять AUR: если да, добавить политику пользователя и состояние; если нет, документация должна явно ограничивать автообход.

## Готово, когда

Успешный пустой вывод helper означает проверено/0; nonzero exit выводится как ошибка, сообщение «Система уже обновлена» не появляется без успешной проверки включённого AUR.

## Ограничение / риск

Сохранить поведение соседних веток, особенно обработку отказа и уже записанное состояние.
