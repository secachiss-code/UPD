# SEC-06 — Отказывать при ошибке создания секрета API?

**Оценка:** подтверждён fail-open путь; отказ /dev/urandom условен. **Источник:** дополнительная перепроверка смежного кода; в `docs/BUGS.md` записи нет.

**Перед началом:** закрыты —. Открыть только этот detail; перепроверить строковые якоря.

## Проверка смежных участков

src/vpn.rs:449–460: буфер из нулей заполняется через /dev/urandom, Result игнорируется; сохранение secret тоже игнорируется. build_config:552 и api:691 вызывают secret() независимо.

## Правка

Изменить secret() на Result<String, String>; read_exact случайных байт и write_private секретного файла должны завершаться успешно до возврата значения. Распространить ошибку через build_config/write_config/api и остальные вызовы. Для уже существующего файла проверять минимум длину и формат, избегать повторной генерации из-за временной ошибки чтения. Не запускать mihomo с константным или несохранённым секретом.

## Готово, когда

При отказе генератора случайных байт или записи файла prepare/api возвращают ошибку и не создают рабочий конфиг с известным секретом; при успешной генерации повторный вызов читает тот же секрет.

## Ограничение / риск

Контроллер слушает 127.0.0.1; предсказуемый секрет расширяет доступ для локальных пользователей.
