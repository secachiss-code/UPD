# Блокировки конфигурации (D07)

| Ресурс | Блокировка | Область |
| --- | --- | --- |
| Тяжёлая CLI/таймерная операция | `state/.lock` | Существующие `with_lock` |
| Файлы VPN, профили, YAML, ядро, геофайлы | `state/.vpn-config.lock` | Генерация/замена файлов, изменение подписок, проверка и сохранение кандидата конфигурации |
| Конфигурация upd | `.<имя конфига>.lock` рядом с конфигом | Перечитывание, изменение, проверка, атомарное сохранение |
| Реестр подписок | `state/.vpn-subs.lock` | Чтение–изменение–сохранение реестра и профилей |
| Очередь изменений настроек helper | `State.settings` | Последовательные ConfigSet внутри helper |
| Текущая операция и подписчики helper | `Mutex<State>` | Короткая проверка ID/владельца, резервирование операции, публикация событий |

Порядок файловых блокировок: `.lock` (если уже взята) → `.vpn-config.lock` → блокировка конфигурации → `.vpn-subs.lock`. `Mutex<State>` не удерживается при ожидании файловой блокировки, polkit, сети, PTY или системной команды. Settings mutex берётся до резервирования операции; status и cancel его не берут.

`Config::save` перечитывает конфигурацию после блокировки и объединяет только поля, изменённые относительно прочитанной версии. Списки зеркал объединяются через добавления и удаления. Сохранённая версия возвращается в изменяемый объект. `Config::update` выполняет изменение свежей версии в одной транзакции. Внутренний `save_locked` не захватывает flock повторно.

`write_config` захватывает блокировку файлов VPN и вызывает внутренний `write_config_locked`. `apply` освобождает файловую блокировку перед reload/restart. Таймер освобождает блокировки файлов и подписок до apply. Блокировку файлов нельзя удерживать при `systemctl start/restart`: ExecStartPre запускает другой процесс upd, который сам генерирует YAML. Это предотвращает ожидание собственной блокировки через systemd.

Все вызовы сохранения из CLI/TUI проходят через транзакционный `Config::save`; helper использует `Config::update`. Изменения настроек и VpnAdd резервируют операцию helper, поэтому конфликтующая установка не запускается параллельно. Внешние CLI/таймерные операции используют те же файловые блокировки. YAML заменяется целиком атомарно.

Без подписки допустимая VPN-настройка сохраняется как pending. Ошибка проверки порта/DNS или профиля возникает до записи. Ответ ConfigSet включает фактически прочитанную сохранённую конфигурацию, её revision и отдельный runtime status. Сбой применения обозначается `saved_but_not_applied`, содержит причину и команду повтора. CLI/TUI также явно сообщают, что настройка сохранена, если последующее применение не удалось.
