# Журнал находок статического аудита

**Объект:** исходники проекта `upd`, Cargo-версия `0.2.2`, ручная и пакетная установка, systemd/cron-интеграция.
**Дата:** 2026-09-25.
**Метод:** чтение исходников, скриптов и конфигурации сборки; анализ потоков данных и ошибок. Сборка, тесты, установленные пакетные менеджеры и реальные службы во время этого аудита не запускались. Поэтому пометка «условно» означает, что проявление зависит от ОС, настроек или поведения внешней программы.

В документ включены проблемы, а не план работ. Для каждой находки указаны критичность, условия проявления, механизм и влияние. Варианты исправления здесь не перечисляются.

## Шкала критичности

- **Высокая** — раскрытие учётных данных, сохранение активного системного маршрута после удаления VPN или потенциальная запись от root за пределы рабочего каталога.
- **Средняя** — возможны потеря пользовательских настроек, неверный статус обновления, обход проверки свободного места или сбой системной интеграции.
- **Низкая** — ограниченный сценарий, ложное уведомление, отказ интерфейса или проблема удобства сопровождения.

## Находки

### SEC-01 — Ошибка обновления подписки раскрывает полный URL

**Критичность:** высокая. **Уверенность:** высокая.

**Где:** `src/vpn.rs:168`, `src/vpn.rs:381`, `src/vpn.rs:440`, `src/common.rs:354`.

**Когда проявляется:** подписка содержит токен в пути или query string либо логин/пароль в URL, и её обновление завершается HTTP-ошибкой или сетевой ошибкой.

`vpn::get` преобразует ошибки `ureq` в строки без удаления URL. В используемом `ureq` представлении HTTP-ошибки содержат адрес запроса. `update_subs` кладёт эту строку в `Sub.error`, после чего `publish_state` записывает её в общий `vpn.json`. JSON-файлы в `/var/lib/upd` сохраняются с правами `0644`, каталог — `0755`. Ошибка также попадает в вывод фонового обслуживания; для systemd это может быть журнал службы.

**Влияние:** пользователи с доступом к общему состоянию или журналу могут получить секретный URL подписки. Это обходит задуманное разделение между закрытым `/etc/upd/vpn/subs.json` и публичным статусом.

### VPN-01 — Удаление последней подписки не выключает уже работающий VPN

**Критичность:** высокая. **Уверенность:** высокая.

**Где:** `src/main.rs:556`, `src/main.rs:561`, `src/main.rs:565`, `src/vpn.rs:342`.

**Когда проявляется:** служба VPN работает, и пользователь удаляет последнюю подписку.

`delete_sub` удаляет профиль и сохраняет пустой список подписок. CLI применяет новый конфиг только при условии, что после операции в списке осталась хотя бы одна подписка. При пустом списке команда завершается без остановки службы и без изменения уже загруженной конфигурации mihomo.

**Влияние:** подписка и профиль удалены с диска, но работающий процесс может продолжить использовать уже загруженные узлы и держать TUN-маршруты. Пользователь видит, что подписок нет, хотя системный VPN ещё активен.

### FS-01 — Путь записи зеркал в `/tmp` предсказуем и передаётся root-утилите

**Критичность:** высокая при успешной гонке. **Уверенность:** условная: требует проверки поведения `rate-mirrors`/`reflector` и системного `fs.protected_symlinks`.

**Где:** `src/backend.rs:86`, `src/backend.rs:191`, `src/backend.rs:194`, `src/backend.rs:197`.

**Когда проявляется:** Arch-система использует `rate-mirrors` или `reflector`, а подбор выполняется от root.

Имя файла имеет вид `/tmp/upd-mirrors.<PID>` и целиком известно коду до запуска внешней утилиты. Путь передаётся утилите как цель `--save`; приложение не создаёт его через безопасный уникальный файловый дескриптор и не проверяет тип/владельца перед записью.

**Влияние:** если атакующему удаётся заранее создать или подменить этот путь и внешняя утилита следует по ссылке, root-процесс может записать данные в произвольный доступный root файл. Даже без успешного перехода по ссылке предсказуемое имя создаёт риск гонки и отказа подбора. Саму гонку в этом статическом аудите не запускал; фактическая возможность зависит от системной защиты ссылок и реализации установленной утилиты.

### SEC-02 — Загрузка исполняемого ядра mihomo продолжается без контрольной суммы

**Критичность:** средняя, потенциальный ущерб высокий. **Уверенность:** высокая.

**Где:** `src/vpn.rs:979`, `src/vpn.rs:982`, `src/vpn.rs:984`, `src/vpn.rs:994`, `src/vpn.rs:1001`.

**Когда проявляется:** GitHub API не содержит поле `digest` для выбранного релизного файла.

В этом случае программа не прерывает установку: скачивает архив по `browser_download_url`, распаковывает бинарник, запускает его проверку `-v` от root и заменяет установленное ядро. Проверка запуска подтверждает только то, что файл стартует; она не удостоверяет его происхождение.

**Влияние:** при компрометации источника релиза, API или канала доставки файл может быть установлен и исполнен с системными привилегиями без сверки целостности. TLS снижает риск обычного перехвата, но не заменяет проверку происхождения артефакта.

### SEC-03 — URL подписки по HTTP передаётся открытым текстом

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/vpn.rs:322`, `src/vpn.rs:323`, `src/vpn.rs:263`.

**Когда проявляется:** пользователь добавляет подписку с `http://`; код принимает как HTTP, так и HTTPS.

URL вместе с запросом передаётся без транспортного шифрования. В URL подписки обычно находится долговременный токен доступа; ответ содержит конфигурацию и адреса серверов.

**Влияние:** узел сети между компьютером и провайдером может прочитать или изменить URL и ответ профиля. Подмена профиля влияет на конфигурацию процесса mihomo, запущенного от root.

### SEC-04 — APT-копия исходных источников доступна с обычными правами состояния

**Критичность:** средняя, при секретах в URI — высокая. **Уверенность:** высокая для прав, условная для наличия секретов.

**Где:** `src/backend.rs:531`, `src/backend.rs:538`, `src/backend.rs:539`, `src/backend.rs:541`, `src/common.rs:354`.

**Когда проявляется:** APT source-файл имеет закрытые права или содержит credentials в URL/соседних строках, а `upd` включает управление зеркалами.

Весь исходный файл сохраняется в `/var/lib/upd/apt-backup.json`. `save_json` принудительно задаёт JSON-файлам режим `0644`; каталог состояния имеет режим `0755`. Переписанный source-файл также создаётся с режимом `0644`. Оригинальный URI отдельно записывается в `apt-original-uri` с правами, определяемыми стандартным umask процесса.

**Влияние:** credentials или другие закрытые строки из APT-конфигурации могут стать читаемыми локальным пользователям, даже если исходный source-файл был закрыт правами.

### SEC-05 — Название VPN-профиля из ответа сервера выводится без очистки управляющих символов

**Критичность:** низкая. **Уверенность:** высокая.

**Где:** `src/vpn.rs:270`, `src/vpn.rs:271`, `src/vpn.rs:281`, `src/main.rs:552`, `src/tui.rs:793`.

**Когда проявляется:** сервер подписки задаёт `profile-title` в base64 или `filename` с ESC/control-последовательностями, а пользователь не ввёл собственное название.

Декодированное имя сохраняется и затем напрямую включается в обычный вывод и строки TUI. Проверки на управляющие символы перед отображением нет.

**Влияние:** недоверенный сервер подписки может влиять на оформление терминала, вставлять ложные строки/ссылки и затруднять чтение статуса. Это возможно только для клиента, который отображает такое имя.

### UPD-01 — Ошибка получения списка пакетов может быть показана как «система обновлена»

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/mirrors.rs:399`, `src/mirrors.rs:401`, `src/main.rs:257`, `src/main.rs:258`, `src/main.rs:269`.

**Когда проявляется:** индексы обновились, но `Backend::updates()` вернул ошибку, например симуляция apt или запрос pacman не смогли получить список.

`gather` сохраняет текст ошибки в `st.error`, оставляя `st.list` пустым. `cmd_update` отдельно обрабатывает только конкретную ошибку обновления баз. Если списки Flatpak, AUR и прошивок тоже пусты, команда выводит «Система уже обновлена» и возвращает `0`, не проверив оставшуюся ошибку.

**Влияние:** пользователь может принять неудачную проверку за отсутствие обновлений; автоматизированный запуск также получает код успешного завершения.

### UPD-02 — Ошибки установки Flatpak и fwupd не меняют итог обновления

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/main.rs:322`, `src/main.rs:324`, `src/main.rs:331`, `src/main.rs:333`, `src/main.rs:345`, `src/main.rs:346`.

**Когда проявляется:** обновление пакетов прошло успешно, но установка Flatpak или прошивки завершилась ошибкой.

Ошибка Flatpak только печатается; `result` остаётся успешным. Результат `firmware_upgrade` полностью игнорируется. До установки прошивки состояние `updates.json` уже очищается, если основной результат успешен.

**Влияние:** команда может вернуть код `0`, напечатать «Обновление завершено» и удалить из сохранённого состояния список Flatpak-обновлений после их неудачной установки. Сбой прошивки также не отражается в коде результата и сохранённом списке.

### UPD-03 — Фоновая команда сообщает systemd об успехе при ошибке проверки или загрузки

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/main.rs:208`, `src/main.rs:224`, `src/main.rs:231`, `src/main.rs:234`.

**Когда проявляется:** `upd auto` не может получить список обновлений либо завершить предзагрузку.

Фоновая команда в конце всегда возвращает `0`. При этом ошибки могут быть записаны в `updates.json` или выведены в журнал, но systemd считает oneshot-сервис успешно завершённым.

**Влияние:** состояние служб не различает успешную фоновую проверку и запуск с ошибкой; мониторинг, опирающийся на exit status systemd, не видит сбой.

### UPD-04 — Ошибки проверки необязательных источников превращаются в пустые списки

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/extras.rs:8`, `src/extras.rs:12`, `src/extras.rs:41`, `src/extras.rs:45`, `src/extras.rs:61`, `src/extras.rs:66`, `src/extras.rs:67`, `src/mirrors.rs:403`, `src/mirrors.rs:406`.

**Когда проявляется:** Flatpak, AUR-helper или fwupd недоступен, завершился с ошибкой или вернул неразбираемый ответ.

Проверки Flatpak/AUR отбрасывают код возврата команды. Ошибка обновления metadata fwupd тоже отбрасывается, а неверный JSON превращается в пустой список. Для этих случаев состояние не содержит отдельной ошибки проверки.

**Влияние:** недоступность источника выглядит так же, как отсутствие обновлений; пользователь может не узнать, что компонент вообще не проверен.

### UPD-05 — Проверка обновлений zypper не проверяет код возврата

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/backend.rs:709`, `src/backend.rs:715`.

**Когда проявляется:** `zypper list-updates` завершается ошибкой, например из-за недоступных репозиториев или ошибки метаданных.

В отличие от dnf-ветки, zypper-ветка берёт только stdout и всегда возвращает `Ok(...)`. Если stdout пустой, `gather` считает, что обновлений нет.

**Влияние:** сбой zypper может стать ложным успешным результатом проверки и далее сообщением «система обновлена».

### UPD-06 — Системный запуск Flatpak не охватывает пользовательские установки

**Критичность:** средняя. **Уверенность:** высокая для отдельных per-user установок.

**Где:** `src/main.rs:237`, `src/extras.rs:8`, `src/extras.rs:20`, `src/extras.rs:24`.

**Когда проявляется:** приложения Flatpak установлены для обычного пользователя, а `upd update`/`upd auto` работает после повышения привилегий до root.

Проверка, предзагрузка и установка запускают Flatpak от имени root. Код не переключается на `SUDO_USER` и не указывает пользовательскую установку. При раздельных system и per-user репозиториях root-команды видят не тот набор приложений.

**Влияние:** обновления per-user приложений могут не отображаться и не устанавливаться, хотя документация описывает Flatpak как компонент общего обновления.

### NET-01 — IPv6-маршрут не участвует в обнаружении сети

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/common.rs:589`, `src/common.rs:602`, `src/common.rs:605`.

**Когда проявляется:** компьютер имеет IPv6-доступ в интернет, но не имеет IPv4 default route и поднятого интерфейса, распознанного как VPN/TUN.

Отпечаток строится только из `/proc/net/route`, то есть IPv4-маршрутов. При отсутствии найденного шлюза `online` становится `false`. `handle_network` на этом основании прекращает обработку.

**Влияние:** смена IPv6-сети не определяется; `upd net` пропускает подбор, а известная старая сеть может быть продолжена без повторной настройки зеркал.

### NET-02 — Все кандидаты зеркал без повторного замера отбрасываются после одного прохода

**Критичность:** низкая. **Уверенность:** высокая.

**Где:** `src/mirrors.rs:179`, `src/mirrors.rs:187`.

**Когда проявляется:** временный сетевой сбой, перегрузка VPN или DNS одновременно ломает каждый первый запрос.

Повторный проход запускается только если после первоначального замера `res` содержит хотя бы один успешный кандидат. Если упали все кандидаты, даже закреплённые вручную и ранее рабочие зеркала не получают второй попытки.

**Влияние:** краткий общий сбой трактуется как отсутствие зеркал; состояние и выбор обновляются менее устойчиво, чем описывает комментарий о повторных замерах.

### NET-03 — Порог 256 КиБ применяется только к timeout, но не к короткому успешному ответу

**Критичность:** низкая. **Уверенность:** высокая.

**Где:** `src/mirrors.rs:49`, `src/mirrors.rs:56`, `src/mirrors.rs:63`, `src/mirrors.rs:65`.

**Когда проявляется:** зеркало или промежуточный captive portal возвращает HTTP 200 с небольшим телом и закрывает ответ штатным EOF.

Комментарий объявляет меньше `PROBE_MIN` нерабочим результатом, но после чтения проверяется только `n == 0`. Небольшое ненулевое тело считается рабочим, если чтение закончилось без ошибки.

**Влияние:** короткая HTML-страница или неполное содержимое может получить хорошую оценку скорости и быть закреплено; реальная загрузка пакетов с этого адреса затем может не работать.

### SPACE-01 — Проверка свободного места может смотреть не на тот каталог и подставлять нулевой размер загрузки

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/mirrors.rs:416`, `src/mirrors.rs:417`, `src/mirrors.rs:418`, `src/mirrors.rs:421`, `src/backend.rs:771`, `src/backend.rs:775`, `src/common.rs:682`.

**Когда проявляется:** оценка размера не удалась или система использует кэш libdnf5 без `/var/cache/dnf`.

`download_size == None` заменяется нулём. Для dnf backend выбирается только первый cache path, хотя список содержит `/var/cache/dnf` и `/var/cache/libdnf5`. Если `statvfs` первого пути завершается ошибкой, `free_space` возвращает `0`, а условие проверки требует `free > 0`.

**Влияние:** `min_free_gb` может проверяться без учёта размера пакетов либо вовсе не проверяться. Предзагрузка способна заполнить диск, несмотря на сообщение, что место было оценено.

### GEO-01 — Геофайл больше 100 МиБ записывается как успешно загруженный, но обрезанный

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/vpn.rs:221`, `src/vpn.rs:223`, `src/vpn.rs:1036`, `src/vpn.rs:1037`, `src/vpn.rs:1038`.

**Когда проявляется:** файл геоданных превышает лимит `100 << 20` байт.

`Read::take(max)` возвращает EOF по достижении лимита без отдельного признака усечения. Любой результат больше 1024 байт записывается в целевой файл и считается успешным; размер исходного ответа и целостность формата не сверяются.

**Влияние:** большой или неожиданно отданный ответ может заменить рабочую базу обрезанным файлом. Следующий запуск mihomo может не загрузить соответствующие правила/геоданные.

### APT-01 — Удаление upd восстанавливает старые копии source-файлов поверх более новых изменений

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/backend.rs:531`, `src/backend.rs:537`, `src/backend.rs:558`, `src/backend.rs:560`.

**Когда проявляется:** администратор редактирует APT-файл-источник после первого включения автоматических зеркал, а затем удаляет `upd`.

При первом изменении сохраняется весь файл. При удалении восстановленная копия целиком перезаписывает текущую версию, без проверки изменений после резервирования.

**Влияние:** добавленные позднее репозитории, suite/component-строки и другие ручные изменения могут исчезнуть. Резервная копия перестаёт представлять текущее пользовательское состояние.

### APT-02 — Перевод источников на mirror+file выполняется несколькими неатомарными шагами

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/backend.rs:531`, `src/backend.rs:538`, `src/backend.rs:539`, `src/backend.rs:554`.

**Когда проявляется:** запись исходного файла, резервной копии или `/etc/apt/upd-mirrors.list` прерывается ошибкой диска/прав между шагами либо обрабатывается несколько source-файлов и сбой происходит посередине.

Сначала сохраняются резервные копии и переписываются ссылки в APT-файлах, а список зеркал записывается после всех этих операций. Общей транзакции или отката уже выполненных записей нет.

**Влияние:** часть source-файлов может ссылаться на новый список при отсутствующем/старом файле зеркал; часть источников может остаться в прежнем состоянии. `apt-get update` может перестать получать индексы до ручного вмешательства.

### INSTALL-01 — `upd install`, запущенный из пакетного `/usr/bin/upd`, может создать параллельную ручную установку

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/main.rs:1072`, `src/main.rs:1074`, `src/main.rs:1076`, `src/main.rs:1080`, `src/main.rs:1082`.

**Когда проявляется:** пакет уже установлен, и пользователь выполняет `sudo upd install` из бинарника `/usr/bin/upd`, не передавая служебный `--package`.

Проверка отказывает только если `/usr/bin/upd` существует и `current_exe` отличается от него. При точном совпадении проверка проходит, после чего `pkg == false` выбирает ручной layout: бинарник копируется в `/usr/local/bin`, юниты и хуки устанавливаются в `/etc`.

**Влияние:** файлы в `/etc` перекрывают пакетные файлы из `/usr/lib`, а `/usr/local/bin` раньше `/usr/bin` в типичном `PATH`. Последующие обновления/удаления пакета могут оставить старые unit-файлы, обращающиеся к уже удалённому бинарнику.

### DATA-01 — Изменения VPN-подписок теряются при параллельных командах

**Критичность:** средняя. **Уверенность:** высокая.

**Где:** `src/vpn.rs:342`, `src/vpn.rs:358`, `src/vpn.rs:367`, `src/vpn.rs:386`; команды запускаются из `src/main.rs:556` и `src/main.rs:573`.

**Когда проявляется:** фоновое `upd auto` обновляет подписки одновременно с ручным `upd vpn add`, `del`, `use` или `update`.

### DATA-03 — Профиль подписки удаляется до подтверждённого сохранения списка

**Критичность:** низкая/средняя. **Уверенность:** высокая.

**Где:** `src/vpn.rs:347`, `src/vpn.rs:349`, `src/vpn.rs:354`; обновление профиля — `src/vpn.rs:285`, `src/vpn.rs:289`.

Удаление подписки сначала убирает файлы профиля, затем сохраняет JSON. При обновлении `fetch_sub` также удаляет старые расширения перед записью нового профиля.

**Влияние:** операция сохранения может оставить подписку в JSON без соответствующего профиля; после ошибки обновления активный runtime ещё может работать, но повторный запуск/перезапуск не сможет загрузить старый профиль.

### SYS-01 — Определение служб с устаревшими библиотеками зависит от cgroup v2

**Критичность:** низкая/средняя. **Уверенность:** высокая.

**Где:** `src/common.rs:825`, `src/common.rs:826`, `src/common.rs:829`.

**Когда проявляется:** systemd работает с иерархией cgroup v1 или hybrid без unified-контроллера.

Из `/proc/<pid>/cgroup` выбирается только строка с префиксом `0::`. В cgroup v1 пути сервисов находятся в строках контроллеров с другими префиксами; `path` остаётся пустым и не совпадает с `/system.slice/...`.

**Влияние:** процессы, удерживающие удалённые библиотеки, могут не попасть в список `upd restart`; соответствующие службы останутся без предупреждения о перезапуске.

### PARSE-01 — Некорректный UTF-8 в имени файла профиля может вызвать panic

**Критичность:** низкая. **Уверенность:** высокая для некорректного заголовка.

**Где:** `src/vpn.rs:128`, `src/vpn.rs:133`, `src/vpn.rs:134`; значение берётся из `src/vpn.rs:275` и `src/vpn.rs:278`.

**Влияние:** ответ подписки может аварийно завершить текущий процесс `upd` при добавлении/обновлении. Это отказ в обслуживании для клиента, использующего такой endpoint.
