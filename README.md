# upd

`upd` — утилита для обновления Linux из терминала. Она объединяет проверку и установку системных пакетов, автоматический выбор зеркал там, где это поддерживается, фоновую предзагрузку, снапшоты и несколько задач обслуживания. В комплекте есть TUI и VPN-служба на базе mihomo.

Текущая версия Cargo-пакета — **0.2.3**. Приложение написано на Rust; проект собирает статический бинарник для `x86_64-unknown-linux-musl`.

## Изменения в 0.2.3

- Сбой проверки пакетов, Flatpak, прошивок, zypper, pacman и AUR больше не выглядит как пустой список обновлений. Если необязательный Flatpak не установлен, проверка пропускается.
- `upd check`, `upd update` и `upd auto` завершаются с ошибкой, когда не удалось проверить источники, применить зеркала или сохранить итог. Ошибка установки Flatpak и прошивок попадает в результат обновления.
- В проверку входят пользовательские установки Flatpak. Неизвестный объём загрузки не подменяется нулём, и в этом случае предзагрузка не обходит запас свободного места.
- Отпечаток сети учитывает IPv6-маршрут по умолчанию. Закреплённые зеркала получают повторный замер, если первый проход целиком неудачный. Смена сети подтверждается только после успешной записи зеркал.
- Резервная копия APT закрыта, права исходного файла сохраняются, переход на `mirror+file:` откатывается при ошибке. При удалении `upd` сохраняются поздние правки администратора; если зеркала вернуть не удалось, удаление прерывается.
- URL подписки не попадает в ошибки и опубликованное состояние. Новые подписки принимаются только по HTTPS. Из названия профиля убираются управляющие символы.
- Секрет API не создаётся, если не удалось прочитать случайные байты или записать файл. Ядро mihomo устанавливается только после проверки SHA-256. Усечённый геофайл не заменяет прежний.
- Удаление последней подписки останавливает VPN. Ошибка перезапуска после обновления ядра сообщается отдельно и не считается успехом. Находится IPv6-listener FlClash.
- Изменения списка подписок сериализуются. Повреждённый `subs.json` отличается от отсутствующего файла. Новый профиль записывается до удаления старого. Ошибка чтения пользовательских правил останавливает сборку конфига.
- Ручная установка из пакетного бинарника запрещена. Удаляются только unit-файлы, принадлежащие `upd`. Модули текущего ядра ищутся и в `/lib/modules`, и в `/usr/lib/modules`. Существующий `/etc/upd.conf` не заменяется значениями по умолчанию, если его не удалось прочитать.
- Собственный код распространяется по MIT; текст лицензии лежит в `LICENSE` и включается в пакеты.

## Установка

Для Arch, Debian/Ubuntu и Fedora/openSUSE можно собрать соответствующий пакет через `./package.sh`, а затем установить его штатным менеджером пакетов. Примеры для собранных пакетов:

```sh
sudo pacman -U upd-0.2.3-1-x86_64.pkg.tar.zst
sudo apt install ./upd_0.2.3-1_amd64.deb
sudo dnf install ./upd-0.2.3-1.x86_64.rpm
```

Для ручной установки скачайте или соберите бинарник и запустите:

```sh
sudo ./upd-linux-amd64 install
```

Команда копирует бинарник в `/usr/local/bin/upd`, устанавливает службы и хуки и выполняет первый подбор зеркал, если он поддерживается системой. Пакетная установка использует `/usr/bin/upd` и сама убирает файлы прежней ручной установки.

Удаление выполняется пакетным менеджером либо `sudo upd uninstall`. Команда старается вернуть исходные зеркала и оставляет настройки и данные в `/etc/upd.conf`, `/etc/upd/vpn` и `/var/lib/upd`.

## Обновление системы

Интерактивное обновление запускается командой `sudo upd update` или первым пунктом TUI.

1. Проверяются смена сети и актуальность замера зеркал; при необходимости зеркала подбираются заново.
2. Обновляются базы пакетного менеджера и собираются списки пакетов, Flatpak, прошивок и (для Arch и производных) новостей Arch. Для загрузки оцениваются требуемое и свободное место.
3. Пакеты предварительно загружаются с повторами. После второй неудачной попытки на системах с управляемыми зеркалами выполняется новый подбор.
4. Перед установкой создаётся снапшот: через `snap-pac`, если тот сам делает снапшоты, иначе через настроенный `snapper` или `timeshift`.
5. Устанавливаются системные пакеты, затем AUR (если доступен `paru` или `yay`) и обновления Flatpak.
6. Можно установить прошивки; затем `upd` показывает службы со старыми библиотеками, необходимость перезагрузки и новые конфигурационные файлы.

Новости Arch выводятся до установки и требуют подтверждения. Проверка свободного места использует каталог кэша выбранного пакетного менеджера; если место определить не удалось, ограничение по размеру не применяется.

## Зеркала и фоновые задачи

Зеркала замеряются реальной загрузкой до 3 МиБ. Результаты хранятся отдельно для отпечатка сети; скорость сглаживается по предыдущим замерам. Учитывается отставание зеркала, если источник сообщает дату синхронизации. Настроенные вручную зеркала проверяются вместе с найденными автоматически.

- Arch: сначала `rate-mirrors` или `reflector`, затем официальный список Arch как запасной источник.
- Ubuntu: региональный список `mirrors.ubuntu.com`.
- Debian: используется CDN `deb.debian.org`; географический подбор не выполняется.
- Fedora/RHEL и openSUSE: зеркала выбирает сам дистрибутив через metalink или MirrorCache.

При поддержке автоматического выбора `upd` закрепляет лучшие зеркала в начале списка. В Arch он также возвращает этот блок, если список перезаписала другая утилита. В Debian/Ubuntu используется файл `/etc/apt/upd-mirrors.list` и механизм apt `mirror+file:`; переход и восстановление выполняются с откатом при ошибке. При удалении `upd` возвращает собственные подстановки, сохраняя добавленные администратором строки; при конфликте оставляет backup и список зеркал для ручного merge.

При установке на systemd настраиваются:

- `upd-auto.timer` — проверка системы и предзагрузка раз в шесть часов;
- `upd-net.timer` — проверка смены сети раз в 15 минут;
- диспетчер NetworkManager — внеплановая проверка при смене соединения;
- пользовательский `upd-notify.timer` — уведомления после входа пользователя.

От батареи фоновая проверка выполняется, но загрузка по умолчанию откладывается. В лимитной сети фоновая задача целиком пропускается. Эти параметры меняются в `/etc/upd.conf`.

## VPN

VPN управляется командой `upd vpn` и systemd-службой `upd-vpn.service`. Ядро mihomo работает от root, чтобы управлять TUN. Поддерживаются импортированные Clash/mihomo YAML-профили и подписки со ссылками узлов. Можно использовать системный TUN или локальный HTTP/SOCKS-прокси, выбирать серверы, задавать правила, DNS и маршрутизацию.

```sh
sudo upd vpn add       # спросит URL в терминале
sudo upd vpn subs
sudo upd vpn start
sudo upd vpn status
sudo upd vpn servers
sudo upd vpn rules
sudo upd vpn stop
```

URL подписки — секрет: он хранится в `/etc/upd/vpn/subs.json` с правами `0600` и не выводится целиком. Команда без аргумента позволяет не помещать URL в историю оболочки. Принимаются только HTTPS-ссылки; перенаправления также разрешены только на HTTPS. Сохранённые ранее HTTP-подписки не обновляются, но уже скачанный профиль не удаляется. Для миграции запросите у провайдера HTTPS-ссылку, добавьте её командой `upd vpn add`, выберите новую подписку через `upd vpn use N`, затем удалите старую через `upd vpn del N`. Если FlClash запущен, запуск `upd vpn start` попросит закрыть его перед запуском второго VPN. Для загрузки недостающих файлов `upd` может использовать обнаруженный локальный прокси FlClash.

Обновление ядра mihomo проверяется во время фонового обслуживания по релизам FlClash. Перед установкой программа требует SHA-256 digest файла релиза из GitHub API и сверяет его; при отсутствии digest или несовпадении суммы установка отменяется. Режимы и все VPN-параметры описаны в [настройках](docs/CONFIGURATION.md); устройство службы и хранение данных — в [обзоре архитектуры](docs/ARCHITECTURE.md).

## Лицензия и внешние проекты

Собственный код `upd` распространяется по [MIT](LICENSE); текст лицензии также включается в пакеты. Внешние проекты сохраняют свои лицензии:

- [FlClash](https://github.com/chen08209/FlClash) — **GPL-3.0** ([LICENSE](https://github.com/chen08209/FlClash/blob/main/LICENSE)). `upd` запрашивает тег его последнего релиза через GitHub API и может использовать прокси уже запущенного FlClash. Исходники и бинарник FlClash в `upd` не включены.
- [mihomo](https://github.com/MetaCubeX/mihomo) — **GPL-3.0** ([LICENSE](https://github.com/MetaCubeX/mihomo/blob/Alpha/LICENSE)). `upd` отдельно загружает ядро из релизов mihomo при настройке VPN; пакет `upd` его не содержит.
- [meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat) — источник геофайлов для mihomo, загружаемых при настройке VPN.

## Команды

```text
upd                         открыть TUI
upd update                  проверить и установить обновления
upd check [--no-download]   проверить и, по умолчанию, скачать пакеты заранее
upd list                    показать последнее сохранённое состояние обновлений
upd status                  показать состояние системы
upd news [--all]            новости Arch после последнего обновления; --all — последние новости
upd mirrors [status|check|rescan|apply|add URL|del URL]
upd snapshots               снапшоты и подсказка по откату
upd restart                 проверить службы и предложить их перезапуск
upd clean                   очистить кэш и удалить ненужные пакеты
upd merge                   открыть pacdiff для файлов .pacnew
upd vpn [help|status|add|subs|use N|del N|update|start|stop|restart]
upd vpn [tun|proxy|rule|global|direct|servers|core|geo|rules]
upd install | uninstall     установить или удалить службу upd
upd version                 вывести версию
```

`auto`, `net`, `notify`, `reconcile` и `gen-files` — служебные команды для таймеров, хуков и сборки пакетов. Для диагностики замера зеркал: `UPD_DEBUG=1 upd mirrors check`.

## Поддерживаемые системы

| Система / менеджер | Обновление | Управление зеркалами | Особенности |
|---|---:|---:|---|
| Arch и производные / pacman | Да | Да, кроме Manjaro | Новости Arch, `.pacnew`, AUR при наличии `paru`/`yay`, snap-pac |
| Debian и производные / apt | Да | `mirror+file:` при наличии codename | Файлы источников сохраняются и возвращаются при удалении |
| Fedora/RHEL / dnf, dnf5, yum | Да | Выбирает дистрибутив | Файлы `.rpmnew` |
| openSUSE / zypper | Да | Выбирает дистрибутив | Для Tumbleweed/Slowroll используется `dup` |

Flatpak, fwupd, snapper, timeshift и systemd используются, если установлены и настроены в системе.

## Настройки и данные

Основной конфигурационный файл — `/etc/upd.conf`. Если его нет, `upd` создаёт его со значениями по умолчанию. Полный список настроек, значения по умолчанию и допустимые диапазоны приведены в [CONFIGURATION.md](docs/CONFIGURATION.md).

Состояние обновлений и замеров зеркал находится в `/var/lib/upd`. Подписки и пользовательские VPN-правила — в `/etc/upd/vpn`; ядро mihomo, сгенерированный конфиг, профили и геофайлы — в `/var/lib/upd/vpn`. URL подписок, сгенерированный конфиг и ключ API защищены правами доступа.

## Сборка пакетов

Нужны Rust, цель musl и системный `gcc`:

```sh
rustup target add x86_64-unknown-linux-musl
./build.sh
./package.sh
```

`build.sh` создаёт `dist/upd-linux-amd64`. `package.sh` собирает Arch, deb и rpm-пакеты в `dist/`; при отсутствии nfpm скачивает закреплённую версию и сверяет её с опубликованным файлом контрольных сумм. Список служб и хуков для пакетов генерирует команда `upd gen-files`.
