# CM — Console Manager

`cm` — утилита для обновления Linux из терминала. Она объединяет проверку и установку системных пакетов, автоматический выбор зеркал там, где это поддерживается, фоновую предзагрузку, снапшоты и несколько задач обслуживания. В комплекте есть TUI и VPN-служба на базе mihomo, а для COSMIC — индикатор на панели и запуск TUI.

Текущая версия Cargo-пакета — **0.2.8**. Приложение написано на Rust; проект собирает статический бинарник для `x86_64-unknown-linux-musl`.

## Изменения в 0.2.8

- Проект переименован в **CM (Console Manager)**: команды `cm`, апплет `cm-cosmic`, службы `cm-*`.
- Первая итерация иконок: терминал `>_` с индикаторами состояния.
- На главном экране — характеристики хоста и CPU, RAM, swap, диск и сетевые скорости с обновлением раз в секунду. `i` открывает подробный статус обслуживания.
- VPN выбирает совместимый User-Agent, проверяет ответ и повторно загружает старые профили с заглушкой при выборе подписки.
- Старые переменные путей `UPD_CONF`, `UPD_STATE_DIR`, `UPD_VPN_ETC` и `UPD_VPN_HOME` поддерживаются как запасные для `CM_*`. При обнаружении старых путей UPD обычная установка и команды CM от root отклоняются, чтобы не записывать конфиг и состояние в каталоги UPD. Для явного перехода ручной UPD 0.2.7 добавлены `cm migration plan`, `cm migration apply` (или `cm install --migrate-upd`) и `cm migration recover`: private backup, журнал и восстановление после прерывания. Нужны остановленные legacy операции; package/foreign layouts и активный VPN не поддерживаются. `help` и `version` доступны; непривилегированное чтение сохраняется. [Реализация и границы перехода](docs/design/cm-network-manager/I01-MIGRATION-IMPLEMENTATION.md) · [Guard обычных команд](docs/design/cm-network-manager/I01-MIGRATION-GUARD.md).

## Изменения в 0.2.7

В выпуске исправлены все 25 замечаний статического аудита из [архива баглиста](docs/BUGLIST.md); актуальное поведение TUI описано в [обзоре интерфейса](docs/TUI-UI-UX.md).

- VPN, безопасность: из профиля подписки берутся только узлы, группы, правила и provider-ы; `listeners`, `dns`, `hosts`, `sniffer`, `authentication`, `skip-auth-prefixes` и прочие ключи отбрасываются. Путь provider-а должен лежать внутри каталога VPN. Профиль разбирается с пределом узлов, глубины и алиасов YAML. При `vpn_allow_lan = 0` прокси слушает только `127.0.0.1`. Геофайлы обновляет только cm, с проверкой формата.
- API mihomo — только Unix-сокет в закрытом каталоге службы, без TCP-порта `9097` и без секрета в заголовке. Перед запросом проверяются владелец сокета и каталога и процесс на другом конце сокета.
- Служба `cm-vpn` работает с ограниченными правами: `CAP_NET_ADMIN`, `CAP_NET_RAW`, `CAP_NET_BIND_SERVICE`, `NoNewPrivileges`, запись только в `/var/lib/cm/vpn`. `ExecStartPre` больше не качает ядро и геофайлы; без ядра служба сразу сообщает `cm vpn core update`.
- Конфликт с другим VPN определяется по чужому TUN или занятому порту прокси/DNS, а не по имени процесса: процесс, назвавшийся `FlClashCore`, запуск не останавливает. Адрес подписки через прокси FlClash уходит только процессу root или пользователя cm.
- Подписки адресуются неизменным id: `cm vpn use|del id:ИД`, TUI использует его сам. Изменение списка между подтверждением и удалением больше не задевает другую запись.
- Вопросы да/нет при закрытом stdin (EOF) отвечают «нет», а не ответ по умолчанию. Пустой Enter по-прежнему — ответ по умолчанию.
- Пределы: вывод внешних команд и ответы сетевых API (AUR, новости, GitHub, списки зеркал, API mihomo) ограничены по объёму, обрезанный список обновлений считается ошибкой. Распакованное ядро ограничено отдельно от архива. Настройки потоков, повторов, таймаутов и часов сжимаются к допустимому диапазону, интервалы считаются без переполнения. Счётчики трафика подписки — точные целые.
- Зеркала: дубликаты убираются за линейное время, повторяются только временные ошибки (таймаут, обрыв, 429, 5xx) — небольшим пулом и с общим бюджетом времени.
- TUI: сбор состояния, поиск AUR, снимки VPN и зеркал, списки снапшотов, истории и новых конфигов и применение настроек идут в фоне; повторные нажатия не плодят потоки, разрыв фоновой задачи показывается ошибкой и позволяет повторить. Кадр только рисует готовые данные, время снимка видно в заголовке, `r` обновляет состояние и текстовые страницы.
- TUI: закрытие экрана команды завершает её оставшихся потомков и поток чтения PTY; экран показывает этапы и итог. Удаление подписки подтверждается постоянной строкой с именем (`y`/`n`). Пустой список серверов объясняет причину, задержка подписана словами. Узкий терминал скрывает второстепенные колонки. Поле ввода показывает допустимый формат и оставляет неверное значение для исправления. После ошибки поиска AUR прежние результаты не показываются и не устанавливаются.

Проверить все сохранённые VPN-профили без переключения активной подписки: `sudo cm vpn doctor`; только вторую подписку: `sudo cm vpn doctor 2`. Проверяются итоговый конфиг и его принятие ядром, а не доступность удалённых серверов. User-Agent для конкретной подписки задаётся командой `sudo cm vpn user-agent 2 'mihomo/1.19.0'`; следующий запрос обновления использует его. Подходящий User-Agent должен соответствовать требованиям сервера подписки.

## Изменения в 0.2.3

- Сбой проверки пакетов, Flatpak, прошивок, zypper, pacman и AUR больше не выглядит как пустой список обновлений. Если необязательный Flatpak не установлен, проверка пропускается.
- `cm check`, `cm update` и `cm auto` завершаются с ошибкой, когда не удалось проверить источники, применить зеркала или сохранить итог. Ошибка установки Flatpak и прошивок попадает в результат обновления.
- В проверку входят пользовательские установки Flatpak. Неизвестный объём загрузки не подменяется нулём, и в этом случае предзагрузка не обходит запас свободного места.
- Отпечаток сети учитывает IPv6-маршрут по умолчанию. Закреплённые зеркала получают повторный замер, если первый проход целиком неудачный. Смена сети подтверждается только после успешной записи зеркал.
- Резервная копия APT закрыта, права исходного файла сохраняются, переход на `mirror+file:` откатывается при ошибке. При удалении `cm` сохраняются поздние правки администратора; если зеркала вернуть не удалось, удаление прерывается.
- URL подписки не попадает в ошибки и опубликованное состояние. Новые подписки принимаются только по HTTPS. Из названия профиля убираются управляющие символы.
- Секрет API не создаётся, если не удалось прочитать случайные байты или записать файл. Ядро mihomo устанавливается только после проверки SHA-256. Усечённый геофайл не заменяет прежний.
- Удаление последней подписки останавливает VPN. Ошибка перезапуска после обновления ядра сообщается отдельно и не считается успехом. Находится IPv6-listener FlClash.
- Изменения списка подписок сериализуются. Повреждённый `subs.json` отличается от отсутствующего файла. Новый профиль записывается до удаления старого. Ошибка чтения пользовательских правил останавливает сборку конфига.
- Ручная установка из пакетного бинарника запрещена. Удаляются только unit-файлы, принадлежащие `cm`. Модули текущего ядра ищутся и в `/lib/modules`, и в `/usr/lib/modules`. Существующий `/etc/cm.conf` не заменяется значениями по умолчанию, если его не удалось прочитать.
- Собственный код распространяется по MIT; текст лицензии лежит в `LICENSE` и включается в пакеты.

## Установка

Для Arch, Debian/Ubuntu и Fedora/openSUSE можно собрать соответствующий пакет через `./package.sh`, а затем установить его штатным менеджером пакетов. Примеры для собранных пакетов:

```sh
sudo pacman -U cm-0.2.8-1-x86_64.pkg.tar.zst
sudo apt install ./cm_0.2.8-1_amd64.deb
sudo dnf install ./cm-0.2.8-1.x86_64.rpm
```

Для ручной установки скачайте или соберите бинарник и запустите:

```sh
sudo ./cm-linux-amd64 install
```

Команда копирует бинарник в `/usr/local/bin/cm`, устанавливает службы и хуки и выполняет первый подбор зеркал, если он поддерживается системой. Если рядом лежит `cm-cosmic-linux-amd64` (его собирает `build.sh`), ставится и интерфейс COSMIC. Пакетная установка использует `/usr/bin/cm` и сама убирает файлы прежней ручной установки; интерфейс COSMIC ставится отдельным пакетом `cm-cosmic`.

Удаление выполняется пакетным менеджером либо `sudo cm uninstall`. Команда старается вернуть исходные зеркала и оставляет настройки и данные в `/etc/cm.conf`, `/etc/cm/vpn` и `/var/lib/cm`.

## Терминальный интерфейс

Запустите `cm` без аргументов. Главное меню сгруппировано по задачам: обновления, сеть и VPN, обслуживание, AUR и настройки. В меню работают стрелки, `j`/`k`, Enter, цифровые клавиши `1`–`9` для первых пунктов и `0` для выхода. Клавиша `i` открывает полный экран состояния; `r` обновляет сведения, `q` или Esc возвращают назад. В широком терминале меню и состояние стоят рядом, в узком меню прокручивается. Подсказки внизу зависят от открытого раздела.

Долгие команды открывают внутри TUI экран выполнения с живым выводом. На вопросы программы отвечайте прямо там; `Ctrl+C` прерывает выполняемую команду, `F4` открывает полный терминал, если нужен его обычный вид. После завершения Enter возвращает на прежний экран. Редакторы файлов и ввод адреса VPN-подписки сразу открываются в полном терминале.

Пункт «Что доступно» показывает сохранённый результат последней проверки и отдельно запрашивает текущие обновления AUR, если они включены и доступен `paru` или `yay`. В VPN вкладки переключаются Tab и клавишами `1`–`3`. Страны в именах серверов TUI показывает кодами вроде `[DE]`, чтобы названия корректно перерисовывались в разных терминалах.

## Интерфейс COSMIC

Апплет «cm» добавляется в Настройках → Рабочий стол → Панель → Апплеты. Нажатие на него открывает TUI в терминале. Запуск cm из меню приложений (`cm-cosmic`) также открывает TUI.

На панели остаётся индикатор: работающий TUI или выполняющаяся операция, ожидание ответа, ошибка, необходимость перезагрузки и число обновлений. Подсказка показывает состояние и время последней проверки. Графическое окно и всплывающая панель действий больше не открываются. Уведомления об обновлениях сохраняются; их кнопки открывают TUI. TUI использует обычное повышение прав через sudo/doas. Повторный запуск использует уже открытый терминал. Отдельный терминал открывается командой `cm-cosmic --new-window` или действием в меню приложения. Поднять окно удаётся у терминалов, доступных через wmctrl; в Wayland окно может потребовать ручного переключения.

## Обновление системы

Интерактивное обновление запускается командой `sudo cm update` или первым пунктом TUI.

1. Проверяются смена сети и актуальность замера зеркал; при необходимости зеркала подбираются заново.
2. Обновляются базы пакетного менеджера и собираются списки пакетов, Flatpak, прошивок и (для Arch и производных) новостей Arch. Для загрузки оцениваются требуемое и свободное место.
3. Пакеты предварительно загружаются с повторами. После второй неудачной попытки на системах с управляемыми зеркалами выполняется новый подбор.
4. Перед установкой создаётся снапшот: через `snap-pac`, если тот сам делает снапшоты, иначе через настроенный `snapper` или `timeshift`.
5. Устанавливаются системные пакеты, затем AUR (если доступен `paru` или `yay`) и обновления Flatpak.
6. Можно установить прошивки; затем `cm` показывает службы со старыми библиотеками, необходимость перезагрузки и новые конфигурационные файлы.

Новости Arch выводятся до установки и требуют подтверждения. Проверка свободного места использует каталог кэша выбранного пакетного менеджера; если место определить не удалось, ограничение по размеру не применяется.

При выборе VPN-подписки cm сначала проверяет новый конфиг через mihomo, затем применяет его и сохраняет выбор. При отказе применения возвращает прежний конфиг; неудачный откат сообщается отдельно. Последняя ошибка с этапом, временем и подпиской хранится в `last-error.json` внутри каталога VPN и показывается командой `cm vpn status` и в TUI. После успешного применения она отмечается как устранённая.

После запуска службы cm ждёт готовности API до 10 секунд. Доступность сервера показывается отдельно: успешный ответ API не означает, что удалённый сервер доступен. TUI использует последний замер mihomo и явно показывает отсутствие замера или его ошибку.

## Зеркала и фоновые задачи

Зеркала замеряются реальной загрузкой до 3 МиБ. Результаты хранятся отдельно для отпечатка сети; скорость сглаживается по предыдущим замерам. Учитывается отставание зеркала, если источник сообщает дату синхронизации. Настроенные вручную зеркала проверяются вместе с найденными автоматически.

- Arch: сначала `rate-mirrors` или `reflector`, затем официальный список Arch как запасной источник.
- Ubuntu: региональный список `mirrors.ubuntu.com`.
- Debian: используется CDN `deb.debian.org`; географический подбор не выполняется.
- Fedora/RHEL и openSUSE: зеркала выбирает сам дистрибутив через metalink или MirrorCache.

При поддержке автоматического выбора `cm` закрепляет лучшие зеркала в начале списка. В Arch он также возвращает этот блок, если список перезаписала другая утилита. В Debian/Ubuntu используется файл `/etc/apt/cm-mirrors.list` и механизм apt `mirror+file:`; переход и восстановление выполняются с откатом при ошибке. При удалении `cm` возвращает собственные подстановки, сохраняя добавленные администратором строки; при конфликте оставляет backup и список зеркал для ручного merge.

При установке на systemd настраиваются:

- `cm-auto.timer` — проверка системы и предзагрузка раз в шесть часов;
- `cm-net.timer` — проверка смены сети раз в 15 минут;
- диспетчер NetworkManager — внеплановая проверка при смене соединения;
- пользовательский `cm-notify.timer` — уведомления после входа пользователя.

От батареи фоновая проверка выполняется, но загрузка по умолчанию откладывается. В лимитной сети фоновая задача целиком пропускается. Эти параметры меняются в `/etc/cm.conf`.

## VPN

VPN управляется командой `cm vpn` и systemd-службой `cm-vpn.service`. Ядро mihomo работает от root, чтобы управлять TUN. Поддерживаются импортированные Clash/mihomo YAML-профили и подписки со ссылками узлов. Можно использовать системный TUN или локальный HTTP/SOCKS-прокси, выбирать серверы, задавать правила, DNS и маршрутизацию.

```sh
sudo cm vpn add       # спросит URL в терминале
sudo cm vpn subs
sudo cm vpn start
sudo cm vpn status
sudo cm vpn servers
sudo cm vpn rules
sudo cm vpn stop
```

URL подписки — секрет: он хранится в `/etc/cm/vpn/subs.json` с правами `0600` и не выводится целиком. Команда без аргумента позволяет не помещать URL в историю оболочки. Принимаются только HTTPS-ссылки; перенаправления также разрешены только на HTTPS. Сохранённые ранее HTTP-подписки не обновляются, но уже скачанный профиль не удаляется. Для миграции запросите у провайдера HTTPS-ссылку, добавьте её командой `cm vpn add`, выберите новую подписку через `cm vpn use N`, затем удалите старую через `cm vpn del N`; вместо номера обе команды также принимают стабильный `id:ИД`. Если работает другой VPN с TUN (FlClash и подобные) или порт прокси/DNS занят, `cm vpn start` попросит устранить конфликт. Для загрузки недостающих файлов `cm` может использовать обнаруженный локальный прокси FlClash, если он запущен от root или от пользователя cm.

Обновление ядра mihomo проверяется во время фонового обслуживания по релизам FlClash. Перед установкой программа требует SHA-256 digest файла релиза из GitHub API и сверяет его; при отсутствии digest или несовпадении суммы установка отменяется. Режимы и все VPN-параметры описаны в [настройках](docs/CONFIGURATION.md); устройство службы и хранение данных — в [обзоре архитектуры](docs/ARCHITECTURE.md).

## Лицензия и внешние проекты

Собственный код `cm` распространяется по [MIT](LICENSE); текст лицензии также включается в пакеты. Внешние проекты сохраняют свои лицензии:

- [FlClash](https://github.com/chen08209/FlClash) — **GPL-3.0** ([LICENSE](https://github.com/chen08209/FlClash/blob/main/LICENSE)). `cm` запрашивает тег его последнего релиза через GitHub API и может использовать прокси уже запущенного FlClash. Исходники и бинарник FlClash в `cm` не включены.
- [mihomo](https://github.com/MetaCubeX/mihomo) — **GPL-3.0** ([LICENSE](https://github.com/MetaCubeX/mihomo/blob/Alpha/LICENSE)). `cm` отдельно загружает ядро из релизов mihomo при настройке VPN; пакет `cm` его не содержит.
- [meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat) — источник геофайлов для mihomo, загружаемых при настройке VPN.

## Поддерживаемые системы

| Система / менеджер | Обновление | Управление зеркалами | Особенности |
|---|---:|---:|---|
| Arch и производные (EndeavourOS, CachyOS, Garuda, Manjaro, Artix…) / pacman | Да | Да, если `[core]` берёт зеркала из `/etc/pacman.d/mirrorlist`; в Manjaro и Artix зеркала оставлены дистрибутиву | Сначала обновляются `*-keyring`, не обновляет систему, загруженную из снапшота; на Garuda установку ведёт `garuda-update`. Новости Arch (кроме Manjaro), `.pacnew`, AUR при наличии `paru`/`yay`, snap-pac |
| Debian и производные / apt | Да | `mirror+file:` при наличии codename | Файлы источников сохраняются и возвращаются при удалении |
| Fedora/RHEL / dnf, dnf5, yum | Да | Выбирает дистрибутив | Файлы `.rpmnew` |
| openSUSE / zypper | Да | Выбирает дистрибутив | Для Tumbleweed/Slowroll используется `dup` |

Flatpak, fwupd, snapper, timeshift и systemd используются, если установлены и настроены в системе.

## Настройки и данные

Основной конфигурационный файл — `/etc/cm.conf`. Если его нет, `cm` создаёт его со значениями по умолчанию. Полный список настроек, значения по умолчанию и допустимые диапазоны приведены в [CONFIGURATION.md](docs/CONFIGURATION.md).

Состояние обновлений и замеров зеркал находится в `/var/lib/cm`. Подписки и пользовательские VPN-правила — в `/etc/cm/vpn`; ядро mihomo, сгенерированный конфиг, профили и геофайлы — в `/var/lib/cm/vpn`. URL подписок, сгенерированный конфиг и ключ API защищены правами доступа.

## Сборка пакетов

Нужны Rust, цель musl и системный `gcc`:

```sh
rustup target add x86_64-unknown-linux-musl
./build.sh
./package.sh
```

`build.sh` создаёт `dist/cm-linux-amd64`, а при наличии заголовков wayland и xkbcommon — и `dist/cm-cosmic-linux-amd64` (glibc; `CM_NO_GUI=1` отключает). `package.sh` собирает Arch, deb и rpm-пакеты в `dist/`, включая пакет `cm-cosmic`, если интерфейс собран; при отсутствии nfpm скачивает закреплённую версию и сверяет её с опубликованным файлом контрольных сумм. Список служб и хуков для пакетов генерирует команда `cm gen-files`.
